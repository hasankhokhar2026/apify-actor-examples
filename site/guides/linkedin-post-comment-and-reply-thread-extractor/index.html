    LinkedIn Post Comment & Reply Thread Extractor: export to CSV, Excel or JSON

    Pull top-level comments from LinkedIn posts, with optional nested reply threads, author identity, reaction counts, and linked profiles found in the comment text.

    This tutorial runs LinkedIn Post Comment & Reply Thread Extractor through the Apify API and saves what it returns as a CSV file, an Excel workbook or JSON, keeping the 7 columns its publisher puts first: authorName, commentText, commentedAt, reactionsCount, isReply, postUrl and scrapedAt.

    What people export it for

    • Audience sentiment — read how people are reacting to a company announcement or thought-leadership post.
    • Lead discovery — surface engaged commenters as warm prospects, filtered to real people by excludeAuthorTypes.
    • Influencer research — see who's actively replying to a creator's posts and how deep the conversation threads go.
    • Brand monitoring — track mentions of your company or product inside comment threads on relevant posts.
    • Community moderation review — pull full reply chains to review how a sensitive post's discussion unfolded.

    Get an API token

    Copy it from Console, Settings, API and Integrations.

    Choose the input

    2 fields are required:

    • postUrls: LinkedIn post URLs to scrape comments from. Accepts formats like: https://www.linkedin.com/feed/update/urn:li:activity:7329761432933134337/ or https://www.linkedin.com/posts/username_some-slug-7329761432933134337/. Use a public, high-engagement post URL for best results. The prefill example uses a Bill Gates post from early 2025.
    • cookie: Your LinkedIn session cookie. Accepts either: (1) the li_at value from browser DevTools → Application → Cookies, or (2) full cookies JSON array exported from an extension like EditThisCookie.

    The schema gives no example for cookie; supply a value before you run it.

    Fix common problems

    Why would authorName be missing from a comment?

    Deleted accounts or heavily restricted profiles can leave author fields empty. If a comment has no extractable ID at all, it's skipped entirely.

    Why did I get fewer comments than maxCommentsPerPost?

    The post may simply have fewer comments, minReactions/excludeAuthorTypes may have dropped some, or LinkedIn may serve that post's comments in a way that only exposes its first batch. Comments are not de-duplicated across different input URLs pointing to the same post.

    Why is a cookie required for public-looking posts?

    LinkedIn's comment data isn't available through any unauthenticated public endpoint, even for posts that appear public in a browser without logging in.

    HTTP 401 means the token is missing; an empty file usually means the input matched nothing, which the run log in Console names.
