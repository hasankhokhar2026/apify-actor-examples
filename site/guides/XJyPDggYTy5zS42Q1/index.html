Use X/Twitter Keyword & Hashtag Tweet Search with Python

Search X (Twitter) by keyword, phrase or hashtag and get tweet text, author, engagement metrics, media and language. Every row says which keyword found it. No login required.

1. Choose the data you need

Review the published README for supported collection modes, examples, and limits. The recipe below uses the current published input definition.

2. Prepare a source-based input

This JSON contains published prefills and required-field defaults. Review every value for your task before running it; it is not a promise of successful collection.

{
  "excludeReplies": false,
  "excludeRetweets": false,
  "keywords": [
    "apify"
  ],
  "language": "Any language",
  "matchMode": "all",
  "maxTweets": 20,
  "monitoringEnabled": false,
  "onlyImages": false,
  "onlyNew": false,
  "onlyQuotes": false,
  "onlyVerifiedUsers": false,
  "onlyVideos": false,
  "searchType": "Latest"
}

Download input.example.json and save your reviewed copy as input.json.

FieldTypeRequiredDescription
keywordsarrayrequiredWords, phrases, hashtags or full X search queries to monitor. Each keyword is searched separately, and every result row tells you which keyword found it (searchTerm).
maxTweetsintegeroptionalStop after this many tweets for each keyword. This is a target, not a guarantee: guest X search returns ~20 posts per answered page, the Phase 6 probes measured 300 unique rows for a 300-row target, and 500/1,000 are unverified.
maxItemsintegeroptionalAlias of Maximum tweets per keyword. The actor accepts either name.
searchTypestringoptionalLatest returns the newest posts first. Top is engagement-ranked output: X's logged-out search never serves the real Top timeline, so the actor collects Latest pages and sorts them by like count client-side.
sortstringoptionalAlias of Result order. The actor accepts either name.
languagestringoptionalOnly return tweets written in this language. Leave the default to search all languages.
dateFromstringoptionalOnly return tweets posted on or after this date. Leave empty for no lower bound.
dateTostringoptionalOnly return tweets posted on or before this date (inclusive). Leave empty for no upper bound.
excludeRetweetsbooleanoptionalSkip retweets/reposts and keep only original posts.
excludeRepliesbooleanoptionalSkip replies and keep only top-level posts.
onlyVerifiedUsersbooleanoptionalOnly return tweets from verified (blue check) accounts.
onlyImagesbooleanoptionalOnly return tweets that contain at least one image.
onlyVideosbooleanoptionalOnly return tweets that contain at least one video or GIF.
onlyQuotesbooleanoptionalOnly return quote tweets (filter:quote).
mentioningstringoptionalOnly return posts that mention this account, e.g. apify or @apify.
authorstringoptionalOnly return posts written by this account, e.g. openai or @openai.
inReplyTostringoptionalOnly return replies addressed to this account, e.g. elonmusk or @elonmusk.
conversationIdstringoptionalOnly return posts in this conversation (the numeric id of the root post).
matchModestringoptionalHow to combine the words in each keyword: all = X's default AND, any = (word1 OR word2), exact = quoted phrase.
excludeWordsarrayoptionalWords or phrases to exclude from every search, compiled to -word / -"two words" tokens.
includeLanesarrayoptionalWhich X search lanes to run: latest, media, media-product, links, replies. Leave empty for the default latest + media + links (replies is added automatically for jobs of 100+ rows). media-product asks for X's product=Media page directly and is opt-in.
maxWindowsintegeroptionalCap the number of backwards time-window passes per keyword. 0 means no explicit cap (the wall-clock budget still applies).
maxPassesintegeroptionalCap the total number of X search passes (core lanes + time windows) per keyword. 0 means no explicit cap.
onlyNewbooleanoptionalReturn only posts newer than the previous run for this keyword. The actor stores a numeric tweet-id watermark plus an overlap window in the key-value store, so scheduled runs do not repeat old rows.
monitoringEnabledbooleanoptionalAlias that enables onlyNew when onlyNew itself is not provided. Prefer the Only new posts field.
monitorIdstringoptionalNamespace for the saved watermark. Use different ids to keep independent schedules for the same keyword. Defaults to 'default'. The legacy alias 'monitoringStateKey' is also accepted.
overlapMinutesintegeroptionalHow far back before the previous run to search, so posts published during the last walk are not missed. Already-seen ids are still filtered out.
maxAgeDaysintegeroptionalNever walk further back than this many days, even when catching up after a long gap.
sinceTimestringoptionalOptional lower bound for a backfill run: ISO 8601 timestamp or Unix epoch seconds. Uses X's epoch since_time operator, not day-granular since:.
untilTimestringoptionalOptional upper bound for a backfill run: ISO 8601 timestamp or Unix epoch seconds. Uses X's epoch until_time operator.
proxyConfigurationobjectoptionalOptional. Use a proxy if you run large jobs or see frequent IP-based rate limits.
startDatestringoptionalDeprecated — use 'Start date' instead. Kept so existing saved inputs keep working. Format: YYYY-MM-DD.
endDatestringoptionalDeprecated — use 'End date' instead. Kept so existing saved inputs keep working. Format: YYYY-MM-DD.

3. Start an Actor run

Set APIFY_TOKEN in your environment. Python 3.10 or newer is sufficient; this recipe uses no third-party packages.

Execution may incur charges. Review current pricing on Apify. The request asks for a 120-second timeout and a charge limit; these settings are subject to Apify’s pricing and do not guarantee an all-inclusive spending cap.

import json
import os
import urllib.request

# Save the schema-derived example as input.json; review and edit it first.
with open("input.json", encoding="utf-8") as stream:
    actor_input = json.load(stream)

token = os.environ["APIFY_TOKEN"]
request = urllib.request.Request(
    "https://api.apify.com/v2/acts/XJyPDggYTy5zS42Q1/runs?timeout=120&maxTotalChargeUsd=0.50",
    data=json.dumps(actor_input).encode("utf-8"),
    headers={"Authorization": "Bearer " + token, "Content-Type": "application/json"},
    method="POST",
)
# This starts a potentially billable run. Do not automatically retry this POST.
with urllib.request.urlopen(request, timeout=40) as response:
    run = json.load(response)["data"]
print("Run ID:", run["id"])
print("Status:", run["status"])
# Inspect and download results in Apify Console once the run succeeds.

Questions before you run

Which inputs are required?

The published required fields are keywords

What does this guide verify?

The fields, prefills, and schema links are rendered from the published build. This is a usage recipe, not a paid live extraction test. Source availability and collection results can vary.

What if the run request times out?

Check Apify Console before retrying. The first request may already have created a run. Do not automatically repeat a run-creation POST.
