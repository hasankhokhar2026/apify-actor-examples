Use Quora Question, Answer & Relationship Dataset Builder with Python

Build a structured Quora dataset from question, answer, profile, Topic, Space, and Post URLs or search terms, with the question-answer-comment chain and relationship links kept intact.

1. Choose the data you need

Review the published README for supported collection modes, examples, and limits. The recipe below uses the current published input definition.

2. Prepare a source-based input

This JSON contains published prefills and required-field defaults. Review every value for your task before running it; it is not a promise of successful collection.

FieldTypeRequiredDescription
scrapeDepthstringoptionalOverview emits page-level summaries without answer/comment/activity/feed expansion; detail preserves the current bounded traversal.
startUrlsarrayoptionalQuestion, answer, profile, topic, Space, or native search URLs.
searchQueriesarrayoptionalNative Quora search seeds. Search cards are followed only when their visible URLs are supported.
questionUrlsarrayoptionalExplicit question-page seeds. Only question routes are accepted.
answerUrlsarrayoptionalExplicit answer-page seeds. Parent question joins are emitted only from observed evidence.
topicUrlsarrayoptionalExplicit Topic-page seeds for bounded visible question discovery.
spaceUrlsarrayoptionalExplicit Space-page seeds for bounded visible feed discovery.
profileUrlsarrayoptionalExplicit profile-page seeds. Only profile routes are accepted; emitted as normalized profile rows exactly like a profile route discovered from startUrls.
postUrlsarrayoptionalExplicit standalone Post-page seeds. Only post routes are accepted; emitted with the same topic_post field family topic-discovered posts use (post_title, post_body, post_author_*).
resultTypesarrayoptionalSelect normalized entities, explicit graph relationships, relationship-collection counts, status rows, and the final run manifest.
outputFormatstringoptionalProjection after one canonical extraction path. Nested groups emitted answers and comments under explicit question/answer parents; flat keeps entity rows with parent context; edges emits explicit edge rows plus status rows.
dedupeModestringoptionalcanonical suppresses overlapping entity rows by stable ID or canonical URL (default); none preserves every observed non-status row. The run manifest reports duplicate_records_suppressed.
onlyNewItemsbooleanoptionalAnnotate canonical entity rows with new/changed/unchanged/scope_mismatch state and suppress only unchanged semantic rows when includeUnchanged is false. Requires stateStoreId; status, graph, and manifest rows remain visible.
includeUnchangedbooleanoptionalRetain unchanged semantic entities when incremental state is enabled; output projection does not alter comparison hashes.
stateStoreIdstringoptionalApify key-value store for canonical entity snapshots. Required when onlyNewItems is enabled; never store cookies or credentials here.
outputFieldsarrayoptionalOptional allowlist for compact rows, including bounded dotted paths through nested collections (for example answers.answer_text, comments.comment_text, feed.feed_text, or contributors.contributor_name where applicable). Child identity/URL fields and the actor identity, access/status, source, traversal, graph, filter, and parser-envelope fields remain protected.
includeFieldEvidencebooleanoptionalInclude field_sources and fields_present maps. Disable only when a smaller payload is required; semantic values and protected access fields remain unchanged.
includeUnresolvedEdgesbooleanoptionalRetain relationship rows whose endpoint URL was not explicitly observed, with unresolved_reason. Disabling this suppresses only those edge rows and does not imply complete relationships.
relationshipTypesarrayoptionalExplicit relationship-type allowlist for the newly ported follower/following/want-answers/upvoter/space-role relationship collections. Empty leaves the existing always-on content-membership/authorship edges untouched (question_has_topic, answer_authored_by, comment_belongs_to_answer, profile_has_activity, space_has_feed_item, etc.); this allowlist only gates the additional collections below. Sensitive follower/want-answer/upvoter types also require includeSensitiveRelationshipData and their matching collection opt-in.
includeProfileEdgesbooleanoptionalEnable explicitly labeled profile follower/following/followed-question/Space/Topic relationship collections. This does not prove a complete list.
includeQuestionFollowerEdgesbooleanoptionalEnable explicitly labeled question follower or want-answer collections. Sensitive identity rows also require the privacy gate.
includeAnswerUpvoterEdgesbooleanoptionalHigh-sensitivity opt-in for explicitly labeled answer upvoter identities; requires includeSensitiveRelationshipData=true.
includeSensitiveRelationshipDatabooleanoptionalExplicit privacy gate required for follower, want-answer, and upvoter identity edges.
includeTargetMetadatabooleanoptionalRetain explicitly visible target link text and image (to_name, to_image_url) on relationship edges. URLs remain evidence; no target navigation or recursive target scraping is performed.
includeRelationshipCountsbooleanoptionalEmit privacy-preserving relationship_collection rows with the real observed total (collection_total_text/collection_total_value) but no target identities. Requires relationship_collection in resultTypes. Observed totals are not always a server-confirmed count.
includeSpaceRoleEdgesbooleanoptionalEnable explicitly labeled Space contributor, moderator, and admin collections.
includeSpaceContentEdgesbooleanoptionalRetain bounded explicit Space post/question membership edges; this never claims a complete Space inventory.
maxRelationshipItemsPerCollectionintegeroptionalBound explicit links emitted from each labeled relationship collection. Zero emits no relationship-collection edges and never means an empty collection.
maxQuestionsintegeroptionalMaximum question seeds or discovered question pages to process.
maxAnswersPerQuestionintegeroptionalMaximum visible answer rows retained from each question page.
maxAnswersintegeroptionalGlobal answer-row cap applied after per-question caps. Zero means no configured global answer cap.
includeQuestionbooleanoptionalRetain normalized question parent rows when selected in resultTypes.
includeAuthorbooleanoptionalRetain visible author fields and profile/profile-activity rows. When false, author fields and author rows are removed from the emitted shape; no contact enrichment is performed.
includeAuthorSnapshotbooleanoptionalOpt into bounded public profile snapshots for visible author profile links; profile access/status is separate from answer/comment success and never includes contact enrichment.
includeTopicsbooleanoptionalRetain explicit topic links and topic relationships where observed.
includeSpacesbooleanoptionalRetain Space rows and feed items where the source route exposes them.
includeCommentsbooleanoptionalEnable bounded visible comment output when the per-answer cap is positive.
includeEngagementBreakdownbooleanoptionalRetain explicitly labeled per-comment reaction breakdowns alongside aggregate reaction labels. Raw labels are preserved and typed companions are added only when the localized number is unambiguous.
includeRelatedContentbooleanoptionalRetain links inside an explicitly labeled related/attached region scoped to answer cards; unlabeled navigation and neighboring regions are excluded.
maxRelatedContentintegeroptionalBound eligible related-content links per answer when enabled; zero emits no related-content items.
topCommentsOnlybooleanoptionalRetain only comments with an explicit visible Top/Most helpful/Popular comments label. Unknown comments are excluded and counted; votes and position are not used as top evidence.
commentSortOrderstringoptionalOrder builder comment rows by observed order or an explicitly typed metric/timestamp. Unknown selected metrics remain in stable fallback order and are counted.
includeReplyGraphbooleanoptionalEnable bounded visible nested comment replies and explicit parent paths; this also enables comment rows. Hidden or unexpanded replies are not inferred.
includeMediabooleanoptionalRequest explicitly rendered media URL fields scoped to question roots, answer/comment nodes, and Topic post cards where the page exposes them.
includeFeedTextbooleanoptionalRequest bounded visible text from explicitly linked Space feed cards; page-level text and complete feed history are excluded.
includeOutboundLinksbooleanoptionalRequest visible non-Quora links scoped to question roots, answer/comment nodes, and Topic post cards; Quora links, comment permalinks, and links outside the owning scope are excluded.
includeEntityGraphbooleanoptionalEmit explicit relationship rows even when entity_edge is not listed in resultTypes.
maxCommentsPerAnswerintegeroptionalMaximum visible comment rows retained per answer when enabled.
maxCommentDepthintegeroptionalMaximum visible nested reply depth when includeReplyGraph is enabled; reaching the bound is not complete history.
maxItemsintegeroptionalCap for normalized entity/status rows before graph and manifest rows.
maxGraphEdgesintegeroptionalIndependent cap for deterministic entity_edge rows.
maxScrollAttemptsintegeroptionalBounded lazy-render scroll budget applied during detail traversal; scroll attempts and termination state are reported.
maxLoadMoreAttemptsintegeroptionalBound exact visible continuation-control clicks on direct question, answer, topic, and Space collection pages independently from scrolling. Search seeds fan out through their discovered child URLs and retain their own source accounting.
includeRawEvidencebooleanoptionalAdd bounded document hash and optional HTML bytes to each page-level entity row.
includeHtmlbooleanoptionalInclude bounded raw-document HTML when raw evidence is enabled and bounded answer-card HTML when answer cards are extracted.
maxHtmlBytesintegeroptionalMaximum UTF-8 bytes retained for optional raw HTML evidence.
requestDelaynumberoptionalDelay between page batches in seconds; this is not an anti-bot bypass guarantee.
maxConcurrencyintegeroptionalMaximum independent seed pages processed concurrently in deterministic batches. Each seed owns a page; discovered seeds merge in batch order.
maxNavigationRetriesintegeroptionalBounded retries after navigation exceptions (e.g. a transient proxy-tunnel handshake failure); exponential backoff is reported in navigation_retry_delays_seconds. Defaults to 2 for reliability.
languagestringoptionalBrowser language hint. Short language codes and supported regional aliases are accepted and normalize to the short code; auto keeps the actor default. This does not translate content or prove access.
cookiesarrayoptionalOptional secret cookies for content the caller is authorized to access.
cookieStringstringoptionalOptional browser-exported name=value; name2=value2 header. Parsed locally into authorized session cookies; the raw header is never emitted or logged.
proxyConfigurationobjectoptionalApify proxy routing. Quora's anti-bot layer blocks the free Datacenter/Automatic tier on roughly half of all real requests (cloud-verified), so this actor always routes through RESIDENTIAL proxies for reliable results regardless of what is selected here — leave this on the default Residential selection unless you need to supply your own proxy URLs.
redactSensitiveQueryParamsbooleanoptionalRedact narrow credential-like query parameter values in emitted URLs, graph endpoints, redirect chains, and raw HTML. The original document hash remains based on the captured document.
rawEvidenceRetentionDaysintegeroptionalWhen zero, suppress raw_html snapshots while retaining hash, size, and redaction diagnostics. Positive values permit bounded HTML for the requested run; external Apify dataset/run retention still applies.
maxRawEvidenceBytesintegeroptionalHard upper byte cap for returned raw HTML after the maxHtmlBytes cap.
maxItemsPerSourceintegeroptionalMaximum semantic records emitted from each direct URL, query, or typed source. Status and run-manifest rows are preserved. Use 0 for no per-source cap.

3. Start an Actor run

Set APIFY_TOKEN in your environment. Python 3.10 or newer is sufficient; this recipe uses no third-party packages.

Execution may incur charges. Review current pricing on Apify. The request asks for a 120-second timeout and a charge limit; these settings are subject to Apify’s pricing and do not guarantee an all-inclusive spending cap.

import json
import os
import urllib.request

# Save the schema-derived example as input.json; review and edit it first.
with open("input.json", encoding="utf-8") as stream:
    actor_input = json.load(stream)

token = os.environ["APIFY_TOKEN"]
request = urllib.request.Request(
    "https://api.apify.com/v2/acts/uAivkcIOWnHGsAnKT/runs?timeout=120&maxTotalChargeUsd=0.50",
    data=json.dumps(actor_input).encode("utf-8"),
    headers={"Authorization": "Bearer " + token, "Content-Type": "application/json"},
    method="POST",
)
# This starts a potentially billable run. Do not automatically retry this POST.
with urllib.request.urlopen(request, timeout=40) as response:
    run = json.load(response)["data"]
print("Run ID:", run["id"])
print("Status:", run["status"])
# Inspect and download results in Apify Console once the run succeeds.

Questions before you run

Which inputs are required?

No top-level fields are marked required in the published schema. Conditional requirements can still apply; check the README.

What does this guide verify?

The fields, prefills, and schema links are rendered from the published build. This is a usage recipe, not a paid live extraction test. Source availability and collection results can vary.

What if the run request times out?

Check Apify Console before retrying. The first request may already have created a run. Do not automatically repeat a run-creation POST.
