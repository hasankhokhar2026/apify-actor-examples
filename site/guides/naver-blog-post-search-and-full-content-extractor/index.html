Use Naver Blog Post Search & Full Content Extractor with Python

Search Naver Blog by keyword, fetch recent posts from a specific blog, or get full post content and tags, with author, blog name, publish date and URLs.

1. Choose the data you need

Review the published README for supported collection modes, examples, and limits. The recipe below uses the current published input definition.

2. Prepare a source-based input

This JSON contains published prefills and required-field defaults. Review every value for your task before running it; it is not a promise of successful collection.

{
  "blogIds": [],
  "categoryNo": 0,
  "includeComments": false,
  "includeContent": false,
  "includeHtml": false,
  "maxComments": 100,
  "maxConcurrency": 3,
  "maxItems": 3,
  "mode": "search",
  "postUrls": [],
  "publishedWithin": "all",
  "searchQueries": [
    "제주도 여행"
  ],
  "sortBy": "sim"
}

Download input.example.json and save your reviewed copy as input.json.

FieldTypeRequiredDescription
modestringrequiredWhat to fetch.
searchQueriesarrayoptionalOne or more Korean or English keywords to search across Naver Blog (mode=search). Each query is searched up to Naver's 1,000-result limit.
blogIdsarrayoptionalNaver blog IDs or blog URLs (mode=blogPosts). Accepts `hello_world123`, `@hello_world123`, or `https://blog.naver.com/hello_world123`.
postUrlsarrayoptionalNaver blog post URLs to fetch in detail (mode=postDetails). Accepts desktop, mobile, PostView, and bare `blogId/logNo` forms.
sortBystringoptionalSort order for keyword search (mode=search).
publishedWithinstringoptionalLimit keyword search results by publish period (mode=search). Choose Custom to use dateFrom and dateTo.
dateFromstringoptionalStart date in YYYY-MM-DD format (KST). Used when publishedWithin=custom (mode=search).
dateTostringoptionalEnd date in YYYY-MM-DD format (KST). Used when publishedWithin=custom (mode=search).
categoryNointegeroptionalNaver blog category number to restrict a blog archive; 0 means all categories (mode=blogPosts).
maxItemsintegeroptionalHard cap on emitted records across all queries, blogs, or URLs.
includeContentbooleanoptionalFetch each post page for full text, exact publish time, images, tags, category, and places. Turn off for faster list-level records.
includeCommentsbooleanoptionalAdd the comment count and comment threads up to maxComments (default 100), including replies when Naver returns them. Implies includeContent=true and adds requests per post.
maxCommentsintegeroptionalMaximum comments to return per post when includeComments is on. Fetched in pages of 100; commentCount still reports the full total.
includeHtmlbooleanoptionalAdd the post body as HTML in contentHtml. Implies includeContent=true.
maxConcurrencyintegeroptionalParallel post-page requests when content enrichment is enabled.

3. Start an Actor run

Set APIFY_TOKEN in your environment. Python 3.10 or newer is sufficient; this recipe uses no third-party packages.

Execution may incur charges. Review current pricing on Apify. The request asks for a 120-second timeout and a charge limit; these settings are subject to Apify’s pricing and do not guarantee an all-inclusive spending cap.

import json
import os
import urllib.request

# Save the schema-derived example as input.json; review and edit it first.
with open("input.json", encoding="utf-8") as stream:
    actor_input = json.load(stream)

token = os.environ["APIFY_TOKEN"]
request = urllib.request.Request(
    "https://api.apify.com/v2/acts/JR9iN0YMYQXCfKan9/runs?timeout=120&maxTotalChargeUsd=0.50",
    data=json.dumps(actor_input).encode("utf-8"),
    headers={"Authorization": "Bearer " + token, "Content-Type": "application/json"},
    method="POST",
)
# This starts a potentially billable run. Do not automatically retry this POST.
with urllib.request.urlopen(request, timeout=40) as response:
    run = json.load(response)["data"]
print("Run ID:", run["id"])
print("Status:", run["status"])
