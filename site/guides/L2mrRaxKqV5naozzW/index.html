Use M.Video Russia Electronics Product & Review Scraper with Python

Search, browse categories, or fetch full product detail from mvideo.ru, including price, rating, specifications, images, seller info, and customer reviews.

1. Choose the data you need

Review the published README for supported collection modes, examples, and limits. The recipe below uses the current published input definition.

2. Prepare a source-based input

This JSON contains published prefills and required-field defaults. Review every value for your task before running it; it is not a promise of successful collection.

FieldTypeRequiredDescription
modestringrequiredWhat to fetch.
searchQuerystringoptionalFree-text product search, e.g. телевизор, ноутбук, холодильник. The full result set is paginated automatically.
citystringoptionalRussian city name or mvideo city ID (e.g. Москва, Санкт-Петербург, CityCZ_975). City changes stock availability, pickup stores and delivery dates.
categorystringoptionalTop-level mvideo.ru category to browse. Use `categoryUrl` for any sub-category not listed here.
categoryUrlstringoptionalOverrides `category`. Accepts a full mvideo.ru category URL (e.g. https://www.mvideo.ru/televizory-i-cifrovoe-tv-1/televizory-65) or a bare numeric category ID, for sub-categories not in the dropdown.
productUrlsarrayoptionalmvideo.ru product URLs (e.g. https://www.mvideo.ru/products/televizor-...-401211841) or bare numeric product IDs. Used by productDetails and reviews modes.
sortOrderstringoptionalResult ordering. Only popularity and price ordering are supported by the source; other orderings are not promised.
brandsarrayoptionalOnly return products from these brands. Accepts brand names or mvideo.ru slugs (e.g. `Samsung`, `samsung`, `LG`). The matching facet is resolved from the live response, so no hardcoded IDs are needed. Multiple values are OR'd together.
sellersarrayoptionalOnly return products from these marketplace sellers. Accepts seller names or mvideo.ru seller slugs (e.g. `BQ.ru`, `bqru`). The seller facet exists in category browsing only; the search response has no seller facet, so a search run with sellers set stops with a clear message. Multiple values are OR'd together.
minPriceintegeroptionalDrop products cheaper than this (sale price, in Russian rubles). Applied server-side in search/category mode and client-side for detail records.
maxPriceintegeroptionalDrop products more expensive than this (sale price, in Russian rubles). Applied server-side in search/category mode and client-side for detail records.
minRatingnumberoptionalDrop products with a customer rating below this (0-5 stars). Applied after catalog fetches (the API has no rating facet). Products with no rating are excluded when this filter is set.
minDiscountintegeroptionalDrop products with a smaller discount than this (0-99 percent). Applied after catalog fetches (the API has no discount facet). Products without a discount are excluded when this filter is set.
conditionstringoptionalFilter by item condition. The matching facet is resolved from the live response; if it is unavailable for a query/category, the run stops with a clear message instead of returning unfiltered results.
fromAbroadbooleanoptionalOnly return parallel-import listings. Applies to search mode only; ignored in category mode.
maxItemsintegeroptionalHard cap on emitted records (products, or review rows in mode=reviews). Search covers the full result set across all pages, de-duplicated by product ID. Use 0 for all (up to the 10,000 cap).
maxReviewsintegeroptionalReviews to fetch per product in mode=productDetails (attached as `reviews[]`) and mode=reviews (one row per review). Paginated 20 at a time; 0 skips review fetching.
includeStoreStockbooleanoptionalFetch per-store pickup availability for the selected city and attach a `stores[]` list.
storeLimitintegeroptionalCap on `stores[]` entries per product when store stock is included.
includeOtherOffersbooleanoptionalFetch the seller/buybox block and attach `otherOffers[]` with prices and seller details when available.
failOnEmptybooleanoptionalMark the run as failed when zero records are emitted (for example a blocked connection or an empty query).
proxyConfigurationobjectoptionalOptional. The actor connects directly first and only escalates to Apify Proxy if mvideo.ru blocks a request. Change this only if you need a specific proxy setup.

3. Start an Actor run

Set APIFY_TOKEN in your environment. Python 3.10 or newer is sufficient; this recipe uses no third-party packages.

Execution may incur charges. Review current pricing on Apify. The request asks for a 120-second timeout and a charge limit; these settings are subject to Apify’s pricing and do not guarantee an all-inclusive spending cap.

import json
import os
import urllib.request

# Save the schema-derived example as input.json; review and edit it first.
with open("input.json", encoding="utf-8") as stream:
    actor_input = json.load(stream)

token = os.environ["APIFY_TOKEN"]
request = urllib.request.Request(
    "https://api.apify.com/v2/acts/L2mrRaxKqV5naozzW/runs?timeout=120&maxTotalChargeUsd=0.50",
    data=json.dumps(actor_input).encode("utf-8"),
    headers={"Authorization": "Bearer " + token, "Content-Type": "application/json"},
    method="POST",
)
# This starts a potentially billable run. Do not automatically retry this POST.
with urllib.request.urlopen(request, timeout=40) as response:
    run = json.load(response)["data"]
print("Run ID:", run["id"])
print("Status:", run["status"])
