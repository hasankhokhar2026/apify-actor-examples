Use TikTok LIVE Room Status & Chat Capture Tool with Python

Check TikTok usernames for an active LIVE stream and get room title, viewer counts, and host profile, or capture real-time chat, gifts, likes, and other events while the stream runs.

1. Choose the data you need

Review the published README for supported collection modes, examples, and limits. The recipe below uses the current published input definition.

2. Prepare a source-based input

This JSON contains published prefills and required-field defaults. Review every value for your task before running it; it is not a promise of successful collection.

{
  "connectionDuration": 10,
  "eventCap": 100,
  "eventTypes": [
    "all"
  ],
  "includeOffline": true,
  "includeStreamUrls": true,
  "mode": "roomStatus",
  "usernames": [
    "natgeo"
  ]
}

Download input.example.json and save your reviewed copy as input.json.

FieldTypeRequiredDescription
modestringrequiredWhat to collect. 'Room status' returns one row per creator (live or offline). 'Live events' attaches to a live room and returns one row per chat/gift/like/follow/share/join/viewer event.
usernamesarrayoptionalTikTok creators to monitor: bare usernames, @handles, profile URLs or LIVE URLs. Duplicates are removed. The prefill checks the National Geographic account.
liveUrlsarrayoptionalDirect TikTok URLs such as https://www.tiktok.com/@creator/live (or a profile URL). An alternative to usernames; both lists are merged.
includeOfflinebooleanoptionalWhen on, every valid creator produces a row even when they are not LIVE (status 'offline', with public profile data). This makes scheduled watchlists and the daily test reliable (mode=roomStatus; ignored in live-events mode).
includeStreamUrlsbooleanoptionalAdd the HLS/FLV playback URL map (and its expiry) for LIVE creators (mode=roomStatus). These URLs are signed by TikTok and stop working when the signature or the stream ends.
connectionDurationintegeroptionalHow long to stay attached to each LIVE room and collect events (mode=liveEvents). A short window is enough for a status check; events need a longer window.
eventCapintegeroptionalStop collecting from a stream after this many events. Applies per stream (mode=liveEvents).
eventTypesarrayoptionalWhich event categories to keep (mode=liveEvents). 'All' keeps every category. 'Other' keeps TikTok message types that do not map to a named category.

3. Start an Actor run

Set APIFY_TOKEN in your environment. Python 3.10 or newer is sufficient; this recipe uses no third-party packages.

Execution may incur charges. Review current pricing on Apify. The request asks for a 120-second timeout and a charge limit; these settings are subject to Apify’s pricing and do not guarantee an all-inclusive spending cap.

import json
import os
import urllib.request

# Save the schema-derived example as input.json; review and edit it first.
with open("input.json", encoding="utf-8") as stream:
    actor_input = json.load(stream)

token = os.environ["APIFY_TOKEN"]
request = urllib.request.Request(
    "https://api.apify.com/v2/acts/wec60fCwOTbQwAqg7/runs?timeout=120&maxTotalChargeUsd=0.50",
    data=json.dumps(actor_input).encode("utf-8"),
    headers={"Authorization": "Bearer " + token, "Content-Type": "application/json"},
    method="POST",
)
# This starts a potentially billable run. Do not automatically retry this POST.
with urllib.request.urlopen(request, timeout=40) as response:
    run = json.load(response)["data"]
print("Run ID:", run["id"])
print("Status:", run["status"])
# Inspect and download results in Apify Console once the run succeeds.

4. Inspect the actual results

Open the run in Apify Console and wait for a successful completion. Use the published output schema to locate results and the dataset schema to understand declared views. Missing or optional record fields must not be treated as guaranteed values.

One row per creator (live status, room metadata, playback URLs, host and audience stats) or one row per real-time LIVE event (chat, gift, like, follow, share, join, viewer count).
