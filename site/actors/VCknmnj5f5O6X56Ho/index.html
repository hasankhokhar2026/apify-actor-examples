Google Play App Search, Lookup & Reviews Scraper

Search Google Play by keyword or look up apps directly by package ID, with ratings, installs, pricing, developer contact details, and optional user reviews across dozens of countries and languages.

Open on ApifyGitHub source

Input schema

Input fields, types, required flags, descriptions, defaults, and prefills come from the published definition. Prefill examples are distinct from defaults.

FieldTypeRequiredDescription
modestringrequiredWhat to scrape.
searchQuerystringoptionalKeyword to search for in mode=search, for example `photo editor` or `calculator`.
appIdsarrayoptionalPackage names or Google Play URLs. Used by details, reviews, similar, permissions, and dataSafety modes.

FieldTypeRequiredDescription
modestringrequiredWhat to scrape.
searchQuerystringoptionalKeyword to search for in mode=search, for example `photo editor` or `calculator`.
appIdsarrayoptionalPackage names or Google Play URLs. Used by details, reviews, similar, permissions, and dataSafety modes.
packageNamesarrayoptionalAndroid package names such as `com.whatsapp`. Play URLs are also accepted.
startUrlsarrayoptionalFull Google Play app URLs, for example `https://play.google.com/store/apps/details?id=com.whatsapp`.
developerIdstringoptionalNumeric Google Play developer ID or a developer page URL, used in mode=developer.
developerNamestringoptionalDisplay name shown on Google Play, for example `Google LLC`, used in mode=developer.
countrystringoptionalStorefront for search results, pricing, and availability. Reviews are selected by Language, not Country.
languagestringoptionalLanguage for app pages and the review bucket. Google Play uses this language, not Country, to choose reviews.
maxItemsintegeroptionalHard cap on dataset rows. Search returns at most 250 apps per query. For similar mode one seed app is one row.
maxReviewsPerAppintegeroptionalReviews to collect for each app. Google Play returns at most 4,500 reviews per page; the actor paginates up to this cap.
reviewSortstringoptionalOrder used when fetching reviews.
includeDetailsbooleanoptionalFetch the full app page for search and developer results, and include app metadata in permissions/dataSafety output. Adds one request per app.
includePermissionsbooleanoptionalAdd the app's permission list to app records. Works in search, details, developer, and similar modes.
includeDataSafetybooleanoptionalAdd shared data, collected data, security practices, and the privacy policy URL to app records.
proxyConfigurationobjectoptionalOptional. The actor works without a proxy; use one only if Google Play blocks your runs.

Google Play App Intelligence Scraper - Details, Reviews & Safety Labels

Collect public Google Play data in one run: keyword search results, full app records, long review histories, developer catalogs, similar apps, permission lists, and data safety labels. Everything is read from public Play pages and RPC endpoints, so no Google account, cookie, or API key is needed.

Modes

Mode What it returns
search Apps matching a keyword, with search rank and an exact-match marker. Add full details, permissions, data safety, or reviews with the toggles.
details One full app record per package name or Play URL.
reviews One flat record per review, with author, rating, text, date, helpful votes, app version, and developer replies.
developer The app catalog for a numeric developer ID or a display name.
similar One record per seed app, with a similarApps array of related apps.
permissions One record per app with grouped and flat permission lists.
dataSafety One record per app with shared data, collected data, security practices, and the privacy policy URL.

What you can collect

App records

  • Identity: id, packageName, name, developer, developerId, developerUrl, url, sourceUrl
  • Ratings: rating, ratingCount, scoreText, reviewCount, histogram
  • Reach and pricing: installs, minInstalls, maxInstalls, price, currency, priceText, free, offersIAP, IAPRange
  • Store metadata: genre, genreId, categories, contentRating, version, updated, released, androidVersion, recentChanges, size when Google publishes it
  • Creative and copy: description, descriptionHTML, summary, icon, headerImage, screenshots, video
  • Developer contact: developerEmail, developerWebsite, developerAddress, developerLegalName, developerLegalEmail, developerLegalAddress, developerLegalPhone, privacyPolicy
  • Search context: searchQuery, rank, isExactMatch
  • Optional trust data: permissions, permissionGroups, dataSafety
  • Optional related data: similarApps, nested reviews
  • Run metadata: recordType, language, country, scrapedAt

Review records

  • id, reviewId, appId, appTitle
  • author, userName, userImage
  • rating, score, text, content, date
  • helpfulCount, thumbsUpCount
  • version, appVersion, criterias
  • developerReply with reply text and date; replyContent and repliedAt are kept for existing integrations
  • reviewUrl, language, storeCountry, sort, recordType, scrapedAt

Permission records

permissions is a flat list of {permission, group, type} objects. permissionGroups keeps Google Play's grouping. Permission names are localised by language.

Data safety records

dataSafety contains sharedData, collectedData, securityPractices, and privacyPolicyUrl. Each shared or collected entry has type, data, optional, and purpose when Google provides them.

Output behaviour

  • Records are omit-empty at every depth. A field Google Play does not publish for an app is left out, never set to null, "", 0, or [].
  • Existing field names from earlier versions (appId, title, score, ratings, lastUpdated, reviewId, content, thumbsUpCount, replyContent, repliedAt, appVersion) are still emitted beside the newer names so saved integrations keep working.
  • Old input keys are mapped in code: searchTerms to searchQuery, maxResults to maxItems, reviewCount to maxReviewsPerApp, and includeReviews to nested reviews on app records.
  • A run that produces zero records fails with a clear status message instead of returning an empty dataset. If some apps fail and others succeed, the dataset is kept and the run ends with a warning summary.
  • RUN_SUMMARY in the key-value store records counts, caps, warnings, errors, and whether any request was blocked.

Limits and honest caps

  • Search: most keywords return 15–50 apps. A minority expose a continuation token; the actor follows it up to 250 apps per query. To collect more, run several queries.
  • Reviews: Google Play serves up to 4,500 reviews per page. maxReviewsPerApp is capped at 50,000 and pagination stops when Google runs out of tokens or returns no new review IDs.
  • Similar apps: up to 150 related apps per seed. Similarity is broad; "similar" means related, not necessarily a direct competitor.
  • Version history: Google Play no longer exposes a version-history page or working RPC. Only the latest version, updated, and recentChanges are returned, and they are absent when Google does not publish them.
  • App size: Google Play's web pages do not expose a download size for most apps. size is emitted only when the source includes it.
  • Developer catalogs: pagination follows the continuation token. A very large publisher can still have more apps than the selected maxItems.
  • Permissions and data safety: these are separate Play endpoints. If one app has no declaration, the record still includes its identity and omits the empty section with a warning.

FAQ

Do I need a Google account, cookie, or API key? No. All seven modes use public Play pages and RPCs that work without authentication.

Does country change reviews? No. country controls the storefront, pricing, search result set, and availability. Reviews are selected by language; this is why the actor keeps the two inputs separate.

Why is a package missing from a search run? Google Play's search covers a limited result set per keyword, and some terms return fewer than 20 apps. Try a broader keyword or add the package directly in packageNames.

What happens when Google blocks a request? The actor retries with bounded exponential backoff. If every request is blocked, the run fails loudly with a blocked-request message. A proxy can be supplied, but it is never required.

Can I mix apps and search in one run? Use details or search with includeDetails, or run separate tasks. Keeping modes separate makes row counts and output shapes predictable.

Is this affiliated with Google? No. This is an independent third-party actor that reads public Google Play pages.
