YouTube Channel Video Feed Quick Scraper

Quickly list any YouTube channel's videos, sorted newest, most popular or oldest, with channel subscriber count, verification and optional Shorts, playlists and live-stream tabs.

YouTube Channel Video Feed Quick Scraper

Point this actor at one or more YouTube channels and get back their video list — newest, most popular or oldest first — with exact publish dates, exact like counts, categories, tags and a full channel profile. It reads YouTube's own public pages, so there is no API key and no login.

What this actor does

  • Accepts any mix of channel handles (@name), full channel URLs, or raw channel IDs across a single run
  • Reads the Videos tab, the channel's uploads playlist (UU{channelId}), or both; the uploads playlist is a complete chronological feed that also includes Shorts and uploads the Videos tab omits. "Both" merges the sources, de-duplicated by video ID, then applies the chosen sort
  • Returns exact publishDate, likeCount, category and tags for each video from YouTube's player response
  • Optionally resolves exact public comment counts per video
  • Sorts videos newest, most popular, or oldest first; Shorts have their own Latest/Popular/Oldest filter
  • Can emit only videos that are new since the previous monitor run
  • Adds derived channel analytics: last upload date, average views, upload gap in days and sample size
  • Optionally pulls the channel's About-page data (total views, join date, location, social links), Shorts, Playlists, and Live/Streams tabs
  • Returns a channel-info-only row (no video fields) when maxVideos is set to 0
  • Applies a country and interface language to every request, including pagination and player endpoints
  • Omits any field YouTube did not expose for that video or channel — it never fills a gap with an empty string or a made-up value

Output per video row

Every video row has recordType: "video" and sourceUrl set to its watch URL, plus the full authorMetadata object for its channel. A channel-info-only row (maxVideos: 0 or a channel with no listed videos) has recordType: "channel" and sourceUrl set to the channel URL. A failed channel emits recordType: "error".

  • recordType, sourceUrl, videoId, title, url
  • viewCount — only when YouTube's own data exposes an exact integer; a rounded label like "93K views" stays in viewCountText and is never converted into a fake exact number
  • viewCountText, publishedTimeText — the relative label exactly as YouTube displays it
  • likeCount — exact integer from the player response, when YouTube exposes it
  • commentCount — exact integer, only when includeCommentCounts is on and the video has a public comment section

FAQ

Is a YouTube API key needed? No — this actor reads YouTube's own public channel and video pages and needs no API key or login.

Which channel reference formats work? A @handle, a full /channel/UC... URL, a full @handle URL, or a raw channel ID all resolve to the same channel.

What is the difference between the Videos tab and the uploads playlist? The Videos tab is a curated 30-per-page list. The uploads playlist (UU + the channel ID without its UC prefix) is the complete chronological feed and returns 100 videos per page. It also includes Shorts and other uploads the Videos tab omits. Use videoSource: "uploadsPlaylist" when coverage matters.

Are like counts exact? Yes. likeCount comes from YouTube's player response as an exact integer. The rounded label YouTube shows in the interface is not used.

Why is commentCount missing? Comment counts are opt-in (includeCommentCounts). They cost up to two extra requests per video: a /next seed request and, when the seed does not already contain the count, a comments-continuation request. When the actor already fetched /next for the description, that response is reused so no second seed request is made. The field is omitted when the video has comments disabled or no public comment section. A count of 0 is a real value and is kept.

Why is viewCount sometimes missing even though viewCountText shows a number? YouTube's video-card label is often rounded (e.g. "93K views"). This actor only fills viewCount when the underlying data gives an exact figure, rather than reverse-engineering an approximate one.

Why would duration show "LIVE" with no durationSeconds? That's an ongoing live stream — its length isn't final yet, so there's nothing finite to report until the broadcast ends.

Does "popular" or "oldest" sort the whole uploads playlist? No. The uploads playlist has no server-side sort menu, so those orders are applied client-side to a scan window of max(maxVideos, min(2 × maxVideos, 60)) videos. For a full-history Popular/Oldest sort, use videoSource: "videosTab", which has YouTube's native sort chips.

Can I filter by exact publish date? Not in this version. Exact dates come from YouTube's player response, which is frequently unavailable to guest requests; exposing a date filter would silently return 0 videos. Use the channel's video list and filter downstream by publishDate when it is present, or use onlyNewVideos for ongoing monitoring.

How does monitor mode store what it has seen? onlyNewVideos keeps a per-channel list of video IDs in the actor's named youtube-channel-monitor key-value store, which persists across runs. The first run returns the normal window; later runs emit only new IDs. Only the rows actually returned are marked as seen, so a maxVideos cap pauses the remaining new videos instead of skipping them permanently.

Does market or language change which videos are returned? market sends the country context (gl) and language sends the interface language (hl) on every page and InnerTube request, including pagination, player and comment calls. They affect localized labels, relative dates, and regionally restricted content. Neither changes which channel you look up.

Can I fetch 5,000+ videos from one channel? Yes — maxVideos goes up to 10,000. With videoSource: "uploadsPlaylist" the actor pages 100 videos at a time until it reaches your cap or the channel's uploads run out. The 10,000 cap is an intentional policy limit, and the exact player-metadata pass has a 900-second budget per run: if that budget runs out on a very large request, the remaining rows keep their listing data (title, view label, relative date) and the run still completes with the full dataset.

What about members-only, age-restricted or private videos? Public listing cards for members-only and age-restricted videos can still be returned, but YouTube gates their playback to signed-in viewers, so playback-only fields (exact metrics, description) may be missing for those rows. Private and deleted videos cannot be fetched at all.

What is recordType? It tells rows apart without inspecting which fields are present: video for normal video rows, channel for the channel-info-only row, and error for a channel that could not be fetched.

Can I get the channel's public business email? No. YouTube only reveals a business email after a Google sign-in and shows a "Sign in to see email address" gate to logged-out visitors. Public social and website links are still returned in externalLinks.

Why are subscriber counts sometimes rounded? YouTube displays subscriber and video counts as rounded labels (e.g. "21.4M subscribers"). The actor keeps that text in subscriberCountText/videoCountText and only fills the integer when YouTube exposes an exact value.
