    YouTube Video Comment & Reply Thread Scraper is an Apify Actor published by Nimbryxo Studio. It accepts 17 input fields, none of them required at the top level. Each result can carry up to 24 declared fields, including recordType, commentId, authorName, text, likeCount and replyCount. It costs $0.99 per 1,000 results on Apify's Free plan and $0.49 on the Business plan.

    What it does

    Scrape YouTube comments and reply threads as analysis-ready rows. Give it video links, channel video tabs, playlists, or search queries, and get one row per comment or reply with author identity, engagement signals, thread position, and video context. Works on public videos without user cookies, login, or an API key.

    What this actor does

    • Four source types: individual videos (watch, Shorts, live, embed, youtu.be, bare ID), channel video tabs, playlists, and video search results
    • Flat rows by default: every comment and reply is its own row with parentCommentId, rootCommentId, replyLevel, and threadPosition, so CSV, Excel, SQL, and sentiment pipelines can use it directly
    • Full reply threads: fetch every page of a thread, cap per comment, or skip replies entirely; maxRepliesPerComment: 0 means all
    • Real filters: Top/Newest sort, date cutoff, multiple keywords (ANY match), minimum likes, and only creator-hearted comments
    • Honest engagement data: rounded like counts with the original text, advertised reply counts, pinned/hearted/verified flags, and approximate dates with a precision and range
    • Video context on every row: title, channel, views, likes, comment count, duration, publish date, and description
    • Empty fields are omitted — records only contain values that are actually populated.

    Use cases

    • Sentiment and topic analysis — export flat comment and reply rows directly into a notebook or BI tool
    • Creator engagement audits — measure which comments the creator pinned, hearted, or replied to
    • Audience research — mine questions and recurring themes across a channel's recent uploads or a playlist
    • Moderation datasets — collect long reply threads with parent/root IDs for context-aware classifiers
    • Campaign monitoring — pull the last few days of comments from several videos with a date cutoff and minimum-like floor
    • Competitive research — compare comment volume and engagement on the same topic across search results

    Status rows

    When emitStatusRows is enabled, blocked/empty/unavailable sources and partial or budget-limited runs add one row with recordType: "status", status, inputUrl, optional video fields, error, and rowsEmitted when known. Status rows are never counted toward maxTotalRows and do not consume the data-row budget. Status values: no_comments, comments_off, unavailable, private, age_restricted, members_only, region_blocked, live_chat_only, blocked, stale_token, transient_empty, parse_empty, partial, budget_reached, input_invalid. Successful comment runs do not add an ok status row.

    Dates and counts are approximate

    YouTube's public comment payload does not expose exact timestamps. Every date field is derived from the relative label (6 years ago) and comes with a precision plus earliest/latest bounds, so no exact timestamp is invented. Like counts above 999 are rounded by YouTube itself; likeCountText preserves the original value. replyCount is YouTube's advertised count and can be higher than the number of replies the public thread returns.

    Questions

    Do I need a YouTube API key or cookies?

    No. The actor reads publicly available comment data without login, user cookies, or an API key. It sends YouTube's standard consent cookie so the EU consent page does not replace the video page.

    Why are some comments missing?

    YouTube's "Top comments" feed exposes a relevance-ordered subset (roughly 800–1,200 comments on very large videos). Use sortBy: "newest" for complete date windows and deeper coverage. The actor also continues with the newest feed when the top feed is exhausted, and maxComments, maxTotalRows, and your filters can all stop a run earlier than the source total.

    Are replies complete?

    The actor follows every reply continuation until the thread token is exhausted when maxRepliesPerComment: 0. YouTube can hide deleted, spam, or moderated replies, so the advertised replyCount may be higher than the rows returned. repliesFetched tells you exactly how many were emitted for a comment.

    Why are timestamps approximate?

    The public comment payload only contains relative labels such as "2 days ago". The actor converts each label into a date range with a precision (hour, day, week, month, year) and exposes the earliest and latest possible time. It never claims an exact timestamp.

    Why do like counts end in round numbers?

    YouTube exposes formatted counts (1.2K, 69K, 4.8M). likeCount is the rounded integer and likeCountText preserves the original string.

    What does a date cutoff do?

    commentsSince forces the newest-first feed, keeps pinned comments, and stops paginating at the first non-pinned comment older than the cutoff. Because dates are approximate, a comment whose range overlaps the cutoff is kept.

    What happens if a video is private, age-restricted, or has comments off?

    The actor classifies the page and, when emitStatusRows is enabled, writes one status row explaining the outcome. It does not try to bypass login, age, or region restrictions.

    What is the difference between flat, tree, and both?

    flat emits one row per comment and reply. tree emits parent comment rows with a replies[] array (useful for older integrations). both emits flat reply rows and also attaches replies[] to each parent.

    Do I need to configure a proxy?

    No. The actor chooses a working connection to YouTube automatically. Just fill in the input and run it.

    Is this affiliated with YouTube?

    No. This is an independent tool and is not affiliated with, endorsed by, or sponsored by YouTube or Google.

    Limits and notes

    Limitations

    • Exact comment timestamps and exact like counts are not available in the public payload.
    • Nested replies beyond direct level 1 are not exposed in the observed public payload; maxReplyDepth above 1 is reserved for future support.
    • The top-comments feed is capped by YouTube; use newest-first plus a date cutoff for exhaustive windows.
    • Age-restricted, private, members-only, and region-blocked videos are reported as statuses, not bypassed.
    • replyCount is advertised, not guaranteed; use repliesFetched for the delivered count.
