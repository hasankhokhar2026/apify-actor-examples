    YouTube Video Comment & Reply Thread Scraper is an Apify Actor published by Nimbryxo Studio. It accepts 17 input fields, none of them required at the top level. Each result can carry up to 24 declared fields, including recordType, commentId, authorName, text, likeCount and replyCount. It costs $0.99 per 1,000 results on Apify's Free plan and $0.49 on the Business plan.

    What it does

    The full README, with every mode, example and answer the publisher documents, is on the Apify Store page. Its sections: “What this actor does”, “Output per comment or reply”, “Input”, “Use cases”, “FAQ” and “Limitations”.

    What you get

    The Actor saves one record per result to an Apify dataset. Its build declares 24 fields in 2 dataset views, and the README documents 33 more. Fields without a value can be left out of a record.

    Run it

    Set APIFY_TOKEN to your Apify API token, then run the Actor with the input below (one video with replies). Each run is billed to your Apify account. The export tutorial turns the results into a CSV file or an Excel workbook.

    Keep the first run small: maxVideosPerSource (default 20, maximum 5000) and maxComments (default 100, maximum 50000) cap how many results a run collects, and so what it costs.

    What it costs

    YouTube Video Comment & Reply Thread Scraper uses pay-per-event pricing: a fee for each result saved to the dataset, plus a start fee per run. Paid Apify plans pay less per result. The start fee is charged once per GB of run memory (at least once); the default run uses 4 GB, so a run starts with 4 start events, as the run totals include. You also pay Apify platform usage (compute and proxy) for the run, which these totals do not include.

    Input reference

    All 17 fields of the published input schema, in the publisher's order. No field is required at the top level, but the README can describe conditions. Download the input schema as JSON.

    Input fields in the published schema
    FieldTypeDescription
    videoUrlsVideo URLs or IDsarrayWatch, youtu.be, Shorts, embed, live, v/ links, or bare 11-character IDs. Every video is normalized to a watch URL internally.Default []; Example ["https://www.youtube.com/watch?v=dQw4w9WgXcQ"]
    channelUrlsChannel URLs or handlesarrayChannel /videos sources: /@handle, /channel/UC..., /c/name, /user/name, a bare @handle, or a UC... channel ID. Scrapes up to Max videos per source.Default []
    playlistUrlsPlaylist URLs or IDsarrayPlaylist sources: youtube.com/playlist?list=... or a bare playlist ID. Scrapes up to Max videos per source.Default []
    searchQueriesSearch queriesarrayYouTube search terms or search-result URLs. Only video results are used, deduplicated, up to Max videos per source.Default []
    maxVideosPerSourceMax videos per channel/playlist/searchintegerDiscovery cap for channel, playlist and search sources. 0 = every video the source exposes.Default 20; Allowed 0 to 5000
    maxCommentsMax top-level comments per videointegerTop-level comments to examine per video. 0 = all. Comments rejected by filters still count toward this scan cap (so restrictive filters cannot paginate forever); replies do not. Both emitted comments and replies count toward Max total rows.Default 100; Example 3; Allowed 0 to 50000
    includeRepliesInclude repliesbooleanFetch reply threads. Emitted as flat rows by default; use Output mode tree to embed them instead.Default true
    maxRepliesPerCommentMax replies per commentintegerPer-thread reply cap. 0 = all replies, stopping when the continuation token is exhausted. YouTube serves roughly 9-10 on the first reply page and 44-49 afterwards.Default 50; Example 3; Allowed 0 to 10000
    maxReplyDepthMax reply depthinteger0 = top-level comments only, 1 = direct replies (the shape observed publicly). Values above 1 are reserved for nested sub-threads, which YouTube has not exposed in the samples used to build this actor.Default 1; Allowed 0 to 6
    maxTotalRowsMax total rowsintegerGlobal budget for emitted comment + reply rows. 0 = unlimited. Status rows are never counted and are not billable data rows.Default 5000; Example 20; Allowed 0 to 1000000
    sortBySort comments bystringtop = YouTube relevance order; newest = chronological, recommended for date cutoffs and complete windows. A date cutoff forces newest automatically.Default "top"; Allowed top, newest
    commentsSinceComments sincestringOptional cutoff as an ISO date/datetime (2026-10-16) or relative duration (7d, 24h, 30m). Forces newest sort. Pinned comments are always kept; pagination stops at the first non-pinned comment older than the cutoff.

    Input fields in the published schema, continued
    FieldTypeDescription
    keywordsKeywords (ANY match)arrayCase-insensitive OR filter on comment and reply text. Empty = no keyword filter. A parent comment that does not match is skipped, so its replies are not fetched.Default []
    minLikesMinimum likesintegerDrop comments and replies below this like count. Applied after fetching. YouTube only exposes rounded counts (K/M), so the comparison uses the rounded value.Default 0; Allowed 0 to 1000000000
    onlyCreatorHeartedOnly creator-hearted commentsbooleanKeep only comments/replies that the video creator hearted. HeartedBy identifies the creator where YouTube exposes the tooltip.Default false
    outputModeOutput modestringflat = one row per comment and reply (recommended for CSV/Excel/SQL); tree = parent rows with embedded replies[] (backward compatible); both = flat rows plus parent rows carrying replies[].Default "flat"; Allowed flat, tree, both
    emitStatusRowsEmit status rowsbooleanWrite one recordType=status row for blocked, private, unavailable, comments-off, empty-token, invalid-input, partial and budget-stop cases. Status rows are never counted toward Max total rows; disable this to keep the dataset data-only.Default true
