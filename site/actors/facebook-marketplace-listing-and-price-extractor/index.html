    Facebook Marketplace Listing & Price Extractor is an Apify Actor published by Nimbryxo Studio. It accepts 27 input fields, none of them required at the top level. Each result can carry up to 75 declared fields, including title, price, city, state, locationText and condition. It costs $0.99 per 1,000 results on Apify's Free plan and $0.49 on the Business plan.

    What it does

    The full README, with every mode, example and answer the publisher documents, is on the Apify Store page. Its sections: “What this actor does”, “Input”, “Output per listing”, “Example: daily prefill”, “Example: keyword search by city” and “Example: deep detail scrape”.

    What you get

    Run it

    Set APIFY_TOKEN to your Apify API token, then run the Actor with the input below (daily prefill). Each run is billed to your Apify account. The export tutorial turns the results into a CSV file or an Excel workbook.

    Keep the first run small: maxItemsPerUrl (default 50, maximum 10000) caps how many results a run collects, and so what it costs.

    What it costs

    Facebook Marketplace Listing & Price Extractor uses pay-per-event pricing: a fee for each result saved to the dataset, plus a start fee per run. Paid Apify plans pay less per result. The start fee is charged once per GB of run memory (at least once); the default run uses 4 GB, so a run starts with 4 start events, as the run totals include. You also pay Apify platform usage (compute and proxy) for the run, which these totals do not include.

    Input reference

    All 27 fields of the published input schema, in the publisher's order. No field is required at the top level, but the README can describe conditions. Download the input schema as JSON.

    Input fields in the published schema
    FieldTypeDescription
    modeModestringWhat to scrape. auto uses startUrls when present and otherwise builds a keyword search. search builds a search from searchQueries plus location. urls scrapes the given Marketplace search, category, or city-feed URLs. items fetches direct item URLs or numeric IDs.Default "auto"; Example "urls"; Allowed auto, search, urls, items
    startUrlsMarketplace URLs or Item IDsarrayMarketplace search, city-category, global-category, city-feed, or /marketplace/item/ URLs. In mode=items, a bare numeric listing ID is also accepted.Default []; Example [{"url": "https://www.facebook.com/marketplace/nyc/search...
    searchQueriesSearch QueriesarrayOne to 20 keywords or phrases (mode=search or mode=auto without URLs). Each query becomes one source.Default []; Example ["laptop"]
    locationLocationstringMarketplace location slug, city, postal code, or address used by keyword search (mode=search or mode=auto without URLs). Examples: nyc, Austin, Texas, 90210, London.Example "nyc"
    countryCountrystringISO 3166-1 alpha-2 country used when resolving a human location. Use GB for London, CA for Toronto, and so on.Default "US"; Allowed AD, AE, AF, AG, AI, AL, AM, AO and 242 more
    latitudeLatitudenumberOptional search center latitude. Provide longitude too.Allowed -90 to 90
    longitudeLongitudenumberOptional search center longitude. Provide latitude too.Allowed -180 to 180
    radiusKmRadius (km)integerSearch radius in kilometres for keyword or category search. URL mode keeps the radius in the URL unless you set this explicitly.Default 65; Allowed 1 to 500
    categoryCategorystringMarketplace category. If searchQueries is empty, the actor opens the city category feed (or the global category feed for a human location). Books, shoes, games, motorcycles, cell-phones, computers, video-games, and cameras were verified as category feeds but expose no server category ID, so they are not usable as keyword filters; use categoryId or a category URL for those.Default "all"; Allowed all, vehicles, electronics, furniture, home, tools, sports, toys and 17 more
    categoryIdCategory IDstringAdvanced numeric Facebook category ID. Takes precedence over category when set.
    sortBySort OrderstringServer-side sort where Marketplace supports it, plus a client-side re-sort by price or posting time. Rows without a price sort last.Default "relevance"; Allowed relevance, newest, oldest, price_asc, price_desc, distance
    minPriceMinimum PricenumberOnly listings at or above this price. Rows without a price are dropped.Allowed at least 0

    FieldTypeDescription
    maxPriceMaximum PricenumberOnly listings at or below this price. Rows without a price are dropped.Allowed at least 0
    conditionConditionstringServer-side condition filter in search/category modes. In deep mode the detail condition is checked too; fast URL rows without condition data are kept.Default "any"; Allowed any, new, used_like_new, used_good, used_fair

    availabilityAvailabilitystringClient-side status filter. Search feeds are mostly available; sold and pending are more common on direct item pages.Default "all"; Allowed all, available, sold, pending
    exactMatchExact Keyword MatchbooleanKeep only rows whose title (and description in deep mode) contains every query word.Default false
    maxItemsMaximum ListingsintegerGlobal output limit across all sources.Default 50; Example 3; Allowed 1 to 10000
    maxItemsPerUrlMaximum Listings Per URLintegerPer-source output limit.Default 50; Example 3; Allowed 1 to 10000
    maxPagesPerUrlMaximum Pages Per URLintegerCost guard for cursor pagination. The actor stops earlier on source exhaustion, a repeated cursor, two empty pages, or maxItems.     scrapeModeScrape Modestringfast streams feed rows. deep fetches each listing page for description, condition, attributes, seller, coordinates, and photos. auto follows includeListingDetails and includeAllPhotos.Default "fast"; Allowed fast, deep, auto

    includeAllPhotosInclude All PhotosbooleanEnables deep mode and adds the full photo gallery.Default false
    rehostImagesRehost ImagesbooleanCopy primary photos and seller avatars into the actor key-value store so the emitted URLs do not expire. The original Facebook URL is kept in primaryPhotoUrlOriginal. When off, mediaUrlTemporary is emitted.Default true; Example false
