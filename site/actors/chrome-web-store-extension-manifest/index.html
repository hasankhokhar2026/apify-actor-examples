    Chrome Web Store Extension Manifest & Permissions Scraper is an Apify Actor published by Nimbryxo Studio. It accepts 27 input fields, and mode is required. Each result can carry up to 14 declared fields, including name, extension_id, developer, rating, rating_count and install_count. It costs $0.99 per 1,000 results on Apify's Free plan and $0.49 on the Business plan.

    What it does

    The Chrome Web Store has no public search API, so auditing extensions at scale usually means opening listing after listing by hand. This actor turns the store's own public pages into structured records: search by keyword, walk a category or theme shelf, pull Trending / Popular / Notable charts, read a curated collection, look up specific URLs, or collect public user reviews. Every extension record includes the published manifest, so permissions, host access, optional permissions, content-script matches and Manifest V2/V3 can be compared without installing anything.

    What this actor does

    • Six ways to discover items: specific URLs or IDs, keyword search, category browsing, editorial top charts, curated collections, and public reviews
    • Full manifest extraction: permissions, optional_permissions, host_permissions, optional_host_permissions, content-script matches, service-worker usage and the complete parsed manifest
    • Publisher intelligence: developer name, email and ID, plus the trader / business disclosures the store publishes (legal name, trade name, address, phone, D-U-N-S number)
    • Privacy signals: the developer's declared data_collected categories and privacy-policy URL
    • Pagination and filters: search and categories are read page by page; filter by rating, install count, featured badge, established publisher, broad host access, item type or developer name
    • Themes too: theme categories and theme search results are labelled with item_type: "theme" and still expose their manifest
    • Reviews mode: public reviews with stars, text, language, app version, helpful votes and developer replies
    • Empty fields are omitted — a key only appears when the store actually publishes a value for that item

    Use cases

    • Permission audits — export every extension in a category and find the ones requesting <all_urls>, cookies, webRequest or broad host access
    • Manifest V2 → V3 tracking — filter by manifest_version to see who has migrated and who has not
    • Competitor monitoring — schedule a category or search run and compare install_count, rating, version and last_updated_at over time
    • Publisher research — build a list of extension makers with the public trader disclosures, website and support links
    • ASO and market mapping — compare category rankings, titles, descriptions and ratings in a niche
    • Security and privacy review — pair permissions with data_collected and privacy_policy_url to see what an extension claims to collect

    Questions

    Does this need a login, cookie or API key?

    No. The actor reads the store's public listing pages and public review pages. No account is required.

    Where does the data come from?

    The public Chrome Web Store listing pages, category pages, top-chart pages, collection pages and the public reviews page. There is no official public search API for store listings.

    Are install counts exact?

    No. The Chrome Web Store publishes rounded bands for larger extensions (for example, 10,000,000 users). Smaller extensions can show exact figures. The actor returns the number exactly as published.

    Are permissions and data collection self-declared?

    Yes. permissions, host_permissions and data_collected come from the manifest and privacy disclosure the developer publishes. They are review signals, not proof that an extension is safe or unsafe.

    Why does an extension lack a long description, publisher address or privacy disclosure?

    Those fields only exist when the store publishes them. Individual developers often have no trader disclosure, and some listings have no privacy-policy URL. Empty fields are omitted rather than filled with placeholders.

    Why are only some related extensions returned?

    The store shows a fixed "similar extensions" shelf. related_extensions keeps the full shelf and relatedExtensionIds is capped at 10 for convenience.

    Can I get every extension in the store in one run?

    No. The store has no public "list everything" endpoint. Search and categories are the paginated surfaces; top charts and collections are fixed curated shelves. Combine categories and search terms for broad coverage.

    Is a category rank available?

    No. The public listing payload exposes the store category and an internal category code, not the item's position inside that category, so the actor omits a fabricated rank.

    Can I get older reviews?

    Yes. Reviews mode pages through the public review feed until maxReviewsPerExtension or maxItems is reached. reviewsSince filters reviews as they are read; paging does not stop at the first older review. The review count shown by the store is the total the store has at that moment.

    Does a high install count mean an extension is trustworthy?

    No. Install counts are rounded and popularity is not a security check. Use the manifest permissions, privacy disclosure and recent reviews together.

    Is this affiliated with Google or the Chrome Web Store?

    No. This is an independent third-party actor that reads publicly available store pages; it is not operated by or affiliated with Google.
