Quora Question, Answer & Relationship Dataset Builder

Build a structured Quora dataset from question, answer, profile, Topic, Space, and Post URLs or search terms, with the question-answer-comment chain and relationship links kept intact.

Open on ApifyGitHub source

Input fields, types, required flags, descriptions, defaults, and prefills come from the published definition. Prefill examples are distinct from defaults.

postUrlsarrayoptionalExplicit standalone Post-page seeds. Only post routes are accepted; emitted with the same topic_post field family topic-discovered posts use (post_title, post_body, post_author_*).
resultTypesarrayoptionalSelect normalized entities, explicit graph relationships, relationship-collection counts, status rows, and the final run manifest.
outputFormatstringoptionalProjection after one canonical extraction path. Nested groups emitted answers and comments under explicit question/answer parents; flat keeps entity rows with parent context; edges emits explicit edge rows plus status rows.
dedupeModestringoptionalcanonical suppresses overlapping entity rows by stable ID or canonical URL (default); none preserves every observed non-status row. The run manifest reports duplicate_records_suppressed.
onlyNewItemsbooleanoptionalAnnotate canonical entity rows with new/changed/unchanged/scope_mismatch state and suppress only unchanged semantic rows when includeUnchanged is false. Requires stateStoreId; status, graph, and manifest rows remain visible.
includeUnchangedbooleanoptionalRetain unchanged semantic entities when incremental state is enabled; output projection does not alter comparison hashes.
stateStoreIdstringoptionalApify key-value store for canonical entity snapshots. Required when onlyNewItems is enabled; never store cookies or credentials here.
outputFieldsarrayoptionalOptional allowlist for compact rows, including bounded dotted paths through nested collections (for example answers.answer_text, comments.comment_text, feed.feed_text, or contributors.contributor_name where applicable). Child identity/URL fields and the actor identity, access/status, source, traversal, graph, filter, and parser-envelope fields remain protected.
includeFieldEvidencebooleanoptionalInclude field_sources and fields_present maps. Disable only when a smaller payload is required; semantic values and protected access fields remain unchanged.
includeUnresolvedEdgesbooleanoptionalRetain relationship rows whose endpoint URL was not explicitly observed, with unresolved_reason. Disabling this suppresses only those edge rows and does not imply complete relationships.
relationshipTypesarrayoptionalExplicit relationship-type allowlist for the newly ported follower/following/want-answers/upvoter/space-role relationship collections. Empty leaves the existing always-on content-membership/authorship edges untouched (question_has_topic, answer_authored_by, comment_belongs_to_answer, profile_has_activity, space_has_feed_item, etc.); this allowlist only gates the additional collections below. Sensitive follower/want-answer/upvoter types also require includeSensitiveRelationshipData and their matching collection opt-in.
includeProfileEdgesbooleanoptionalEnable explicitly labeled profile follower/following/followed-question/Space/Topic relationship collections. This does not prove a complete list.
includeQuestionFollowerEdgesbooleanoptionalEnable explicitly labeled question follower or want-answer collections. Sensitive identity rows also require the privacy gate.
includeAnswerUpvoterEdgesbooleanoptionalHigh-sensitivity opt-in for explicitly labeled answer upvoter identities; requires includeSensitiveRelationshipData=true.
includeSensitiveRelationshipDatabooleanoptionalExplicit privacy gate required for follower, want-answer, and upvoter identity edges.
includeTargetMetadatabooleanoptionalRetain explicitly visible target link text and image (to_name, to_image_url) on relationship edges. URLs remain evidence; no target navigation or recursive target scraping is performed.
includeRelationshipCountsbooleanoptionalEmit privacy-preserving relationship_collection rows with the real observed total (collection_total_text/collection_total_value) but no target identities. Requires relationship_collection in resultTypes. Observed totals are not always a server-confirmed count.
includeSpaceRoleEdgesbooleanoptionalEnable explicitly labeled Space contributor, moderator, and admin collections.
includeSpaceContentEdgesbooleanoptionalRetain bounded explicit Space post/question membership edges; this never claims a complete Space inventory.
maxRelationshipItemsPerCollectionintegeroptionalBound explicit links emitted from each labeled relationship collection. Zero emits no relationship-collection edges and never means an empty collection.
maxQuestionsintegeroptionalMaximum question seeds or discovered question pages to process.
maxAnswersPerQuestionintegeroptionalMaximum answer rows retained per question after SSR and GraphQL pagination.
maxAnswersintegeroptionalGlobal answer-row cap applied after per-question caps. Zero means no configured global answer cap.
includeQuestionbooleanoptionalRetain normalized question parent rows when selected in resultTypes.
includeAuthorbooleanoptionalRetain visible author fields and profile/profile-activity rows. When false, author fields and author rows are removed from the emitted shape; no contact enrichment is performed.
includeAuthorSnapshotbooleanoptionalOpt into bounded public profile snapshots for visible author profile links; profile access/status is separate from answer/comment success and never includes contact enrichment.
includeTopicsbooleanoptionalRetain explicit topic links and topic relationships where observed.
includeSpacesbooleanoptionalRetain Space rows and SSR feed items. Explicit spaceUrls enable this automatically.
includeCommentsbooleanoptionalOpt-in comment rows from Quora's public comment-area GraphQL. robots-sensitive; off by default. When enabled and maxCommentsPerAnswer is 0, the documented fallback is 10 per answer.
includeEngagementBreakdownbooleanoptionalRetain explicitly labeled per-comment reaction breakdowns alongside aggregate reaction labels. Raw labels are preserved and typed companions are added only when the localized number is unambiguous.
includeRelatedContentbooleanoptionalRetain links inside an explicitly labeled related/attached region scoped to answer cards; unlabeled navigation and neighboring regions are excluded.
maxRelatedContentintegeroptionalBound eligible related-content links per answer when enabled; zero emits no related-content items.
topCommentsOnlybooleanoptionalRetain only comments with an explicit visible Top/Most helpful/Popular comments label. Unknown comments are excluded and counted; votes and position are not used as top evidence.
commentSortOrderstringoptionalOrder builder comment rows by observed order or an explicitly typed metric/timestamp. Unknown selected metrics remain in stable fallback order and are counted.
includeReplyGraphbooleanoptionalEnable comment rows plus one-level nested reply extraction from repliesConnection. Requires includeComments.
includeMediabooleanoptionalRequest explicitly rendered media URL fields scoped to question roots, answer/comment nodes, and Topic post cards where the page exposes them.
includeFeedTextbooleanoptionalRequest bounded visible text from explicitly linked Space feed cards; page-level text and complete feed history are excluded.
includeOutboundLinksbooleanoptionalRequest visible non-Quora links scoped to question roots, answer/comment nodes, and Topic post cards; Quora links, comment permalinks, and links outside the owning scope are excluded.
includeEntityGraphbooleanoptionalEmit explicit relationship rows even when entity_edge is not listed in resultTypes.
maxCommentsPerAnswerintegeroptionalMaximum comment rows retained per answer when comments are enabled. Schema default 0 is kept for compatibility; comments-enabled runs treat 0 as 10.
maxCommentDepthintegeroptionalMaximum nested reply depth when includeCommentReplies/includeReplyGraph is enabled.
maxItemsintegeroptionalCap for normalized entity/status rows before graph and manifest rows.
maxGraphEdgesintegeroptionalIndependent cap for deterministic entity_edge rows.
maxScrollAttemptsintegeroptionalBounded lazy-render scroll budget applied during detail traversal; scroll attempts and termination state are reported.
maxLoadMoreAttemptsintegeroptionalBound exact visible continuation-control clicks on direct question, answer, topic, and Space collection pages independently from scrolling. Search seeds fan out through their discovered child URLs and retain their own source accounting.
includeRawEvidencebooleanoptionalAdd bounded document hash and optional HTML bytes to each page-level entity row.
includeHtmlbooleanoptionalInclude bounded raw-document HTML when raw evidence is enabled and bounded answer-card HTML when answer cards are extracted.
maxHtmlBytesintegeroptionalMaximum UTF-8 bytes retained for optional raw HTML evidence.
requestDelaynumberoptionalDelay between page batches in seconds; this is not an anti-bot bypass guarantee.
maxConcurrencyintegeroptionalMaximum independent seed pages processed concurrently in deterministic batches. Each seed owns a page; discovered seeds merge in batch order.
maxNavigationRetriesintegeroptionalBounded retries after navigation exceptions (e.g. a transient proxy-tunnel handshake failure); exponential backoff is reported in navigation_retry_delays_seconds. Defaults to 2 for reliability.
languagestringoptionalBrowser language hint. Short language codes and supported regional aliases are accepted and normalize to the short code; auto keeps the actor default. This does not translate content or prove access.
proxyConfigurationobjectoptionalOptional proxy override. The actor starts with a direct connection, retries a fresh session on 403/429, then uses Apify AUTO datacenter proxies, and only falls back to RESIDENTIAL as a proven last resort. Leave this unset; a missing proxyConfiguration never stops the run.
redactSensitiveQueryParamsbooleanoptionalRedact narrow credential-like query parameter values in emitted URLs, graph endpoints, redirect chains, and raw HTML. The original document hash remains based on the captured document.
rawEvidenceRetentionDaysintegeroptionalWhen zero, suppress raw_html snapshots while retaining hash, size, and redaction diagnostics. Positive values permit bounded HTML for the requested run; external Apify dataset/run retention still applies.
maxRawEvidenceBytesintegeroptionalHard upper byte cap for returned raw HTML after the maxHtmlBytes cap.
maxItemsPerSourceintegeroptionalMaximum semantic records emitted from each direct URL, query, or typed source. Status and run-manifest rows are preserved. Use 0 for no per-source cap.
searchDiscoverystringoptionalHow searchQueries are handled. relatedOnly attempts Quora's public search and otherwise emits search_unavailable; bestEffortIndex queries a public web index for indexed Quora URLs. Native Quora search is never claimed.
maxRelatedQuestionsintegeroptionalRelated questions to enqueue per question/topic seed. The page usually exposes 26-35; zero disables related-question discovery.
searchResultsPerQueryintegeroptionalMaximum indexed URLs to use per search query when searchDiscovery=bestEffortIndex.
maxAnswerPagesintegeroptionalBound QuestionPagedListPaginationQuery pages. Zero derives a bound from maxAnswersPerQuestion.
maxTopicFeedPagesintegeroptionalBound topic-feed GraphQL pages when includeTopicFeed is enabled.
maxSpaceFeedBundlesintegeroptionalBound Space feed bundles read from the SSR multifeed.
includeCommentRepliesbooleanoptionalInclude nested repliesConnection rows. Requires includeComments. Comments are robots-sensitive and opt-in; zero-row/blocked results produce a status row.
includeQuoraPlusPreviewbooleanoptionalEmit preview-only answers flagged answer_is_quora_plus/answer_text_completeness=preview. The gated remainder is never fetched or presented as full text.
includeProfileStatsbooleanoptionalEmit follower/following/answer/question/post/view counts, joined date, credentials and expertise topics for profile rows.
includeTopicStatsbooleanoptionalEmit topic follower count and most-viewed authors for topic rows.
includeSpaceStatsbooleanoptionalEmit Space follower/member/contributor/moderator/admin counts, description, icon and cover.
includePostStatsbooleanoptionalEmit post upvotes/views/shares/comments, effective access and question-summary flag.
includeAnswerStatsbooleanoptionalEmit answer counters, dates, AI flag, effective access and Quora+ preview flags.
includeTopicFeedbooleanoptionalOpt into the browser topic-feed GraphQL endpoint. robots-sensitive: keep off unless you accept that compliance caveat.
includeQuestionAuditbooleanoptionalOpt into the public question /log page to fill question_created_at, question_view_count and the asker fields. robots.txt disallows /*/log for generic agents; the actor never includes this in the default prefill.
includeProfileHistorybooleanoptionalOpt into the public profile answer/question tab GraphQL and emit bounded profile_activity rows. robots-sensitive and rate-sensitive; on a 400/403 the run keeps a profile_history_unavailable status row.
maxProfileHistoryPagesintegeroptionalBound for each profile history list (answers and questions) when includeProfileHistory is enabled. Zero derives three pages; one page is roughly ten items.
maxRelationshipPagesintegeroptionalBound for each public identity-list query (question followers, answer upvoters, profile followers/following, Space roles) after the relationship allowlist and privacy gates. Zero is treated as one page.

Quora Question, Answer & Relationship Dataset Builder

Build a structured Quora dataset from direct links or best-effort search discovery. Point it at question, answer, profile, Topic, Space, or Post URLs and it returns normalized rows for every entity it finds, with the question → answer → comment chain and author/topic links kept intact. Choose how deep to go, how the rows are shaped, and which relationship or feed data to include.

This is an independent, third-party actor. It is not affiliated with, endorsed by, or licensed by Quora, Inc. No Quora account, login, session cookie, or paid proxy is used or required.

What this actor does

  • Accepts question, answer, profile, Topic, Space, and Post URLs directly, plus best-effort search discovery. Typed seed lists (questionUrls, answerUrls, topicUrls, spaceUrls, profileUrls, postUrls) override route auto-detection.
  • Empty fields are omitted; a missing field means the source did not expose it, never null or a sentinel.
  • Parses Quora's server-rendered Relay payloads and double-decodes the window.ansFrontendGlobals.data.inlineQueryResults .push() strings; it does not depend on CSS classes or DOM selectors for the core fields.
  • Paginates question answers with Quora's public QuestionPagedListPaginationQuery cursor, up to maxAnswersPerQuestion / maxAnswers / maxAnswerPages. Every paginated answer is checked against the page question (title/path, linkedQuestion, originalQuestionIfDifferent, and the answer permalink), so unrelated promoted answers cannot become dataset rows while legitimate merged variants still pass.
  • Paginates comment areas and nested replies through AllCommentsListQuery (10+ pages with after cursors), with maxCommentsPerAnswer as the hard cap; this is opt-in and robots-sensitive.
  • Optionally reads a Topic feed, a Space SSR multifeed, profile statistics, Topic statistics, and Post metrics.
  • Optionally reads the public question /log audit for created time, view count, and asker identity (includeQuestionAudit), and paginates profile answer/question history (includeProfileHistory).
  • Optionally resolves public identity lists for question followers, answer upvoters, profile followers/following, and Space roles through explicitly requested relationship types and the sensitive-data gate.
  • Walks the question → answer → comment chain and keeps the links between them (entity_edge rows), so you can rebuild the conversation tree.
  • Offers four output shapes via outputFormat: normalized (separate rows per entity, default), nested (answers grouped under their question, comments under their answer), flat, and edges (relationship rows plus any status rows).
  • Reports a status row (rather than guessing) whenever a page is blocked, login-gated, removed, or otherwise inaccessible, and a run_manifest row summarizing the whole run.
  • Leaves empty content fields out of each row rather than filling them with a guess. 0 and false are kept as real values.
  • Never emits cookie/credential material. URLs are redacted when redactSensitiveQueryParams is on.

Output per record

Trimming rows, depth, sessions and caps

  • Field allowlist. outputFields keeps only the fields you name, applied after extraction; an empty list returns the full row. Nested projection is supported with dotted paths such as answers.answer_text or answers.comments.comment_text in nested output. Child identity/URL fields stay in place, and content_type, identity, access/status, depth, timing and parser fields are always protected so a trimmed row can still be traced. output_projection on each row reads full or selected, and the run manifest records the requested fields. includeFieldEvidence toggles the field_sources/fields_present maps.
  • Depth. scrapeDepth: "detail" (default) runs the capped traversal; overview emits page-level summaries without answer, comment, profile-activity or Space-feed expansion. Every row reports requested_depth, observed_depth and detail_expansion_state. bounded means a configured cap was reached, not that Quora's full history was collected, and blocked pages report observed_depth: "status".
  • Caps. maxAnswersPerQuestion bounds each question, maxAnswers is a global answer cap, maxAnswerPages bounds GraphQL pages explicitly, maxItems caps entity/status rows before graph/manifest rows, maxItemsPerSource caps each source, and maxGraphEdges caps relationship rows. When maxItems/maxGraphEdges is 0 the corresponding cap is off. maxRelationshipItemsPerCollection bounds each labeled relationship collection, maxRelationshipPages bounds each public identity-list query, and maxProfileHistoryPages bounds each profile answer/question list. answer_pagination_limited is emitted only when a configured page cap or a GraphQL rate limit stopped pagination; an exhausted source is not reported as a cap.
  • Comments. Set includeComments: true. When maxCommentsPerAnswer is 0, the documented fallback is 10 per answer. The actor calls AllCommentsListQuery with after cursors and a page size derived from your cap (up to 50), so a 24-comment answer is collected as 10 + 10 + 4 when the server pages at ten. includeCommentReplies (or includeReplyGraph) expands nested replies up to maxCommentDepth; comment_page_limited is set only when a cap is actually hit, and a comments_capped status row follows. If the paginated query fails, the actor falls back to the first-page loader rather than inventing rows. Comments use Quora's comment-area GraphQL, which robots.txt disallows for generic agents: keep this opt-in and review your own compliance posture.
  • Topic feed. Set includeTopicFeed: true to call the topic page's own public GraphQL feed. maxTopicFeedPages bounds pages. This path is also robots-sensitive; keep it opt-in.
  • Question audit. includeQuestionAudit: true reads the question's public /log page for question_created_at, question_view_count, question_merge_count, and the asker name/uid/profile/credential. It retries a transient 403 once, then keeps question_audit_state: "unavailable" and a question_audit_unavailable status row. /log is robots-disallowed for generic agents and is never part of the daily prefill.
  • Profile history. includeProfileHistory: true paginates UserProfileAnswersMostRecent_RecentAnswers_Query and UserProfileQuestionsList_Questions_Query and emits bounded profile_activity rows. maxProfileHistoryPages (default 0 = three pages per list) and requestDelay (used as a 1.5–2.5 s GraphQL pace when above zero) bound the work. A cap sets profile_history_limited; a 400/403 sets profile_history_state: "rate_limited" and a profile_history_unavailable status row instead of fabricated rows.
  • Identity lists. Identity rows are emitted only when relationshipTypes explicitly requests them, the matching family flag is on, and includeSensitiveRelationshipData is on for sensitive types. The public GraphQL operations cover profile followers/following people/questions/Spaces/Topics, question followers, answer upvoters, and Space admins/contributors/moderators/followers. maxRelationshipItemsPerCollection and maxRelationshipPages bound every list; Space role calls run from a www.quora.com page context. These lists are robots-sensitive and rate-sensitive; a failure keeps a relationship_identity_unavailable or relationship_identities_not_observed status row, and a page/item cap adds relationship_identity_capped.
  • Sessions and proxies. No account, login, cookie, or session secret is used. The transport ladder is direct (curl_cffi, fresh session per attempt) → optional user proxy override → Apify AUTO datacenter → RESIDENTIAL only as a hardcoded last resort after the free rungs fail. A missing proxyConfiguration never stops the run, and there is no paid default. proxy_path_used reports the rung that worked.
  • Exact field names. Every output field this actor can emit is listed under Output per record above. Fields whose source is absent on a given page are omitted, not set to null or a sentinel.

FAQ

Do I need a Quora account? No. Direct public question, answer, profile, Topic, Space, and Post pages are read without login. The actor never asks for, stores, or emits cookies or session secrets.

Why did I get a status row instead of question/answer data? Quora showed a login wall, Cloudflare challenge, a removed page, or an unsupported redirect for that URL. The actor reports this honestly as a status row instead of guessing at data that was not there. A run with zero real rows also gets a no_records_emitted status row and a non-success status message.

Why do I sometimes get fewer answers than maxAnswersPerQuestion? The actor reads the server-rendered answers, filters out answers whose question is provably unrelated, then paginates the public GraphQL cursor up to your cap. If the question genuinely has fewer answers, the cursor stops; you get the answers that were observable and no answer_pagination_limited row, because the source was exhausted rather than capped. answer_pagination_limited appears only when maxAnswerPages/your cap stopped a non-exhausted source or Quora rate-limited a pagination request, and the page's known answerCount is not already satisfied; a non-rate GraphQL failure uses answer_pagination_unavailable. Neither case fabricates an answer.

How do I get question created time, view count, or the asker? Set includeQuestionAudit: true. The actor reads the public /<question>/log page (robots-sensitive, opt-in) and fills question_created_at, question_view_count, question_merge_count, and the question_author_* fields. Without it, those fields are omitted rather than guessed. A blocked /log leaves question_audit_state: "unavailable" and a status row.

How do I get more than the three visible profile history items? Set includeProfileHistory: true. The actor paginates the public answer/question tab connections into profile_activity rows, bounded by maxProfileHistoryPages and paced by requestDelay. This GraphQL path is robots- and rate-sensitive; a 400/403 leaves a profile_history_unavailable status row and no fabricated rows.

What is the difference between the four outputFormat values? normalized keeps every entity as its own row (the default). nested groups each question's answers (and each answer's comments) underneath it; rows without a matching parent stay at the top level with an orphan reason. flat is like normalized, except answer rows also get question context and comment rows get answer_url. edges returns the relationship rows between entities plus any status rows.

Can I get a Quora account's followers, question followers, answer upvoters, or Space roles? Yes, as explicit opt-ins. Request the relationship type in relationshipTypes, turn on the matching family flag (includeProfileEdges, includeQuestionFollowerEdges, includeAnswerUpvoterEdges, or includeSpaceRoleEdges), and set includeSensitiveRelationshipData: true for follower/upvoter/want-answer types. The actor then calls the public identity-list GraphQL operations, paginates up to maxRelationshipPages, and emits only identities whose profile/question/Space/Topic URLs it observed. It may also use visible DOM links as a fallback. These paths are robots- and rate-sensitive; failures produce relationship_identity_unavailable or relationship_identities_not_observed status rows. It never invents identities.

What does the incremental re-scrape (onlyNewItems) actually compare? It hashes each entity's semantic content and compares it to the previous run stored under stateStoreId, tagging each row new, changed, unchanged, or scope_mismatch (the previous run used different settings). Rows are only dropped when onlyNewItems is on and includeUnchanged is off. Status and manifest rows are never dropped by this setting. If any requested source did not finish, the new state is not saved and a state_store_uncommitted status row tells you so.

Why are some text/media fields missing even with includeMedia/includeHtml on? Those fields are only populated when Quora's public payload actually contains that content for the entity in question. The toggles request the data; they do not guarantee every entity has it.

Is search native Quora search? No. Quora's native /search?q= is login/Cloudflare-gated for logged-out clients and is disallowed by robots.txt. searchQueries uses related-question discovery by default and an optional third-party best-effort index; if no public results are discoverable it emits a search_unavailable status row.

What are the hard limitations? Native Quora search is not available cookielessly: /search?q= redirects and the public search GraphQL returns no connection. Quora+ smart_distribution answers may be preview/truncated; they are flagged answer_is_quora_plus and their observed completeness is reported, and no gated remainder is fabricated. Space all-time views/upvotes/comments are private (tested across ten diverse Spaces), Topic description and question count are absent, and question description is absent. Space allTimeFollowers is emitted as space_all_time_followers only when the payload carries it (not every Space does).

Question created/view/asker, full profile history, comment/reply pagination, and identity lists are technically available through public pages/GraphQL but are robots-sensitive and/or rate-sensitive opt-ins; they are off by default and not part of the daily prefill. Be aware that robots.txt for generic agents disallows / broadly, including /*_POST, /*/log, /*/followers, /*/following, and /*/comments; product/legal review decides whether to enable those opt-ins. Quora URLs are valid in a browser, but plain HTTP clients can receive a Cloudflare 403 on HEAD/GET; the actor fetches them with TLS impersonation.

Is this affiliated with Quora? No. This is an independent, third-party actor that reads public Quora pages; it is not affiliated with or endorsed by Quora, Inc. You are responsible for how you use the data.
