    Facebook Timeline Posts & Reel Transcript Extractor is an Apify Actor published by Nimbryxo Studio. It accepts 19 input fields, and startUrls is required. Each result can carry up to 14 declared fields, including postId, postType, text, author.name, reactionsTotal and commentsCount. It costs $0.99 per 1,000 results on Apify's Free plan and $0.49 on the Business plan.

    What it does

    The full README, with every mode, example and answer the publisher documents, is on the Apify Store page. Its sections: “What this actor does”, “Output per post”, “Input”, “Use cases” and “FAQ”.

    What you get

    The Actor saves one record per result to an Apify dataset. Its build declares 14 fields in 3 dataset views, and the README documents 19 more. Fields without a value can be left out of a record.

    Run it

    Set APIFY_TOKEN to your Apify API token, then run the Actor with the input below (last 30 days of a brand's reels, with transcripts). Each run is billed to your Apify account. The export tutorial turns the results into a CSV file or an Excel workbook.

    Keep the first run small: maxCommentsPerPost (default 100, maximum 5000) caps how many results a run collects, and so what it costs.

    What it costs

    Facebook Timeline Posts & Reel Transcript Extractor uses pay-per-event pricing: a fee for each result saved to the dataset, plus a start fee per run. Paid Apify plans pay less per result. The start fee is charged once per GB of run memory (at least once); the default run uses 4 GB, so a run starts with 4 start events, as the run totals include. You also pay Apify platform usage (compute and proxy) for the run, which these totals do not include.

    Input fields in the published schema
    FieldTypeDescription
    startUrlsFacebook linksarray requiredMix any public Facebook links. A Page or Profile link (facebook.com/nike, profile.php?id=…, /people/…/…) returns its timeline posts. A post, reel, video, photo, watch, share (facebook.com/share/…, fb.watch/…), permalink.php, story.php or public group post link returns that single post. Group feeds, events, Marketplace and search pages are not supported.Example [{"url": "https://www.facebook.com/pepsi/posts/1054998311...
    maxItemsMax posts per Page or ProfileintegerHow many posts to collect from each Page or Profile link, newest first. Posts removed by the filters below don't count. Single post links always return one post.Default 20; Example 1; Allowed 1 to 10000
    onlyPostsNewerThanOnly posts newer thanstringPage and Profile links only: keep posts published after this moment. Accepts a date (2026-01-01), a full ISO 8601 timestamp, or a relative period such as "7 days", "2 weeks", "3 months" or "1 year".
    onlyPostsOlderThanOnly posts older thanstringPage and Profile links only: keep posts published before this moment. Same formats as "Only posts newer than". Combine both for a date window.
    contentTypesContent typesarrayPage and Profile links only: keep only these kinds of posts. Leave empty to keep everything. When matching posts are rare, the timeline scan stops after 20 × the post limit (at least 50) scanned posts and the run status says so.Default []; Allowed text, photo, album, video, reel, link, share, live
    minReactionsMinimum reactionsintegerPage and Profile links only: skip posts with fewer reactions than this.Allowed 0 to 100000000
    minCommentsMinimum commentsintegerPage and Profile links only: skip posts with fewer comments than this.Allowed 0 to 100000000
    includeTopCommentsInclude top commentsbooleanAttach the comments Facebook shows under each post (about 1-10 per post) at no extra cost.Default true; Example false
    fetchAllCommentsFetch all commentsbooleanCollect the full comment list of every post into allComments, up to the limit below. Adds a few requests per post.Default false
    maxCommentsPerPostMax comments per postintegerUpper limit for allComments on each post. Replies count toward this limit when replies are included.Default 100; Allowed 1 to 5000
    commentsSortOrderComment orderstringOrder in which allComments are collected. "Newest first" is the best choice for monitoring recent discussion.Default "mostRelevant"; Allowed mostRelevant, newest, all
    onlyCommentsNewerThanOnly comments newer thanstringKeep only comments posted after this moment in allComments: a date (2026-01-01), ISO timestamp, or period such as "1 day" or "2 weeks". Comments are then read newest first.
