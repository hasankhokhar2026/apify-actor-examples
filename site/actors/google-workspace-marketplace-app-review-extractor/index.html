    Google Workspace Marketplace App Review Extractor by App ID is an Apify Actor published by Nimbryxo Studio. It accepts 10 input fields, none of them required at the top level. Each result can carry up to 11 declared fields, including reviewId, appName, appId, rating, reviewText and reviewDate. It costs $0.99 per 1,000 results on Apify's Free plan and $0.49 on the Business plan.

    What it does

    Collect the public user reviews of any Google Workspace Marketplace app - stars, review text, date, reviewer, helpful votes and the developer's replies - for one app or a whole watchlist. No Google account, cookie, API key or proxy is needed.

    The actor paginates the public review list and deduplicates overlapping pages, so a request for 100 reviews returns 100 unique reviews instead of repeated first-page rows.

    What this actor does

    • One row per review - rating, text, date, reviewer, helpful votes and developer replies
    • Multiple apps - pass app IDs or full Marketplace URLs in one run
    • Pagination - follows the public review list page by page and removes duplicates
    • Filters - rating range, date window and review-text keyword
    • Languages - 28 Marketplace language slices or the mixed "All languages" stream
    • App context - developer, listing rating, exact installs, pricing class, icon and links
    • Empty fields are omitted - never null, blank or placeholder values

    Use cases

    • App due diligence - read recent complaints and developer responses before adopting an add-on
    • Review monitoring - track new reviews for a watchlist of Marketplace apps
    • Competitive research - compare ratings, installs and feedback across similar apps
    • Product quality - surface recurring issues by rating, date or keyword
    • Localization QA - inspect reviews in a specific language slice

    Questions

    How many reviews can I collect?

    Up to 2,000 per app (maxReviewsPerApp) and up to 5,000 per run (maxItems). The Marketplace serves text reviews in 10-review pages; rating-only reviews have no body and are not part of the text review total.

    Why does an app show thousands of ratings but fewer text reviews?

    The listing's rating count includes rating-only reviews. The review service returns reviews with text, split by language. Both numbers are real.

    Why pick a language?

    The site serves one language slice at a time. reviewLanguage gives the complete slice for that language. all uses the site's mixed "All languages" stream, whose total can be shorter than the sum of the individual language slices.

    Are review names always present?

    Most reviews show a public name and avatar; some are anonymous. Those fields are omitted rather than filled with a placeholder.

    Do all apps have developer replies?

    Replies are shown when the developer posted one. They are attached to the reviews that carry them; the actor never invents a reply.

    Are HighestRated and LowestRated real Marketplace sorts?

    The Marketplace only offers helpful and newest ordering. The actor fetches newest reviews and sorts that window by stars. Increase maxReviewsPerApp to widen the window.

    Can I search for apps by keyword?

    This actor takes app IDs or URLs. Keyword app discovery is a separate Marketplace surface; use the ID from any app URL.

    Can I monitor new reviews?

    Use sinceDate (for example 7 days) on a schedule; the actor returns only reviews in that window. Cross-run "new since last run" state is not part of this extractor.

    A URL field looks broken?

    App icons, banners and reviewer avatars are public lh3.googleusercontent.com URLs and return images without cookies. Listing pages are public HTML. If an app's own terms/privacy/support link is dead, that is the publisher's link, not a scrape error.

    What about an invalid App ID?

    The Marketplace returns HTTP 400 for an unknown ID. The actor reports it in the status message and continues with the other apps.

    Limits and notes

    Reliability and coverage

    • Pagination stops at the source total, repeated pages with no new review IDs, the per-app cap, or a safety page cap. Review IDs are deduplicated, so page overlap never produces duplicate rows.
    • Replies are attached to the reviews that carry them.
    • Rating, date and keyword filters are applied to the fetched reviews. Restrictive filters scan more pages automatically; raise maxReviewsPerApp for deeper history.
    • Network errors are retried on 429/5xx. A bad App ID is skipped with a clear status message, and the remaining apps still run.
    • No proxy, no cookies: no account, login, cookie, API key or proxy setup is needed.

    Limitations

    • Caps are 2,000 reviews per app and 5,000 per run.
    • The Marketplace exposes two real server sorts; HighestRated/LowestRated sort the fetched window client-side.
    • Reviewer names, avatars and developer replies can be absent upstream; missing values are omitted, never filled.
    • Per-review permalinks are not published; sourceUrl is the app page.
    • Restrictive filters scan a bounded page budget; raise maxReviewsPerApp for deeper history.
