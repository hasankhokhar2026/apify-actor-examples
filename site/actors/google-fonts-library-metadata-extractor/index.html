    Google Fonts Library Metadata Extractor is an Apify Actor published by Nimbryxo Studio. It accepts 15 input fields, and mode is required. Each result can carry up to 20 declared fields, including family, category, isVariable, weights, subsets and designers. It costs $0.99 per 1,000 results on Apify's Free plan and $0.49 on the Business plan.

    What it does

    Get structured metadata for Google's free, open-source font library instead of reading it off the fonts.google.com catalog by hand. Look a family up by name, browse a category, search/filter/sort the whole library, and optionally pull license/attribution plus self-hosting file URLs (woff2, unicode ranges, TTF).

    No login, API key, cookie, or proxy configuration is required.

    What this actor does

    • Four modes: byFamily, byCategory, listAll, icons
    • Search and filters: free text, language subsets, designers, variable-only, color-only, brand/Noto flags
    • Sorting: catalog order, popularity, trending, date added, last modified, alphabetical (icons: popularity or name)
    • Every family: weights, style variants, variable-font axes, subsets, designers, popularity/trending, dates
    • Icons: Material Icons/Symbols names, codepoints, versions, categories, tags, sizes, supported/unsupported families from one request
    • Optional license pack: license id/name/URL, copyright, source repository/commit, source date, languages, unicode coverage, description
    • Optional self-hosting pack: full CSS2 URL, woff2 files with unicode ranges, and TTF download URLs
    • Safe defaults: missing families or category fall back to Roboto / Sans Serif; empty runs are prevented
    • Typed errors: missing_input, not_found, invalid_category, fetch_failed, css_failed
    • Empty fields are omitted: records only contain data that actually exists.

    Use cases

    • Design systems — build a searchable, filterable font picker from live Google Fonts data
    • Self-hosting / GDPR reviews — pull license, copyright, source repo, woff2/unicode-range, and TTF URLs
    • Web performance — request only the weights/styles and file URLs you need before self-hosting
    • Typography research — analyse the library by category, popularity, trend, variable/color support, or date
    • Icon catalogs — export Material icon names, codepoints, categories, tags, sizes, and family support
    • Localization — filter families by language subset (Cyrillic, Greek, Vietnamese, and more)

    Questions

    Where does the data come from?

    The public Google Fonts metadata catalog that powers fonts.google.com, plus the public per-family metadata endpoint, the google/fonts repository, the public download manifest, and (for icons) the public icon metadata endpoint. No login or API key is required.

    How many fonts are covered?

    The entire library — about 1,959 families today. listAll returns all of them up to maxItems (default 5,000; maximum 5,000). icons mode covers a separate Material icon catalog of about 6,139 icons, also capped by maxItems.

    What are the categories?

    Sans Serif, Serif, Display, Handwriting, and Monospace.

    What's the difference between weights and variants?

    weights lists distinct numeric weights (e.g. 400, 700). variants lists every shipped style, including italics (e.g. 400, 400i, 700, 700i).

    What are axes and axisDetails?

    axes lists the variable-font controls (wght, wdth, slnt, opsz, and custom tags) with min, max, and defaultValue. axisDetails adds the catalog's display name and description for those axis tags.

    What's the difference between cssUrl and css2UrlFull?

    cssUrl is the legacy family-only URL, which serves only weight 400. css2UrlFull encodes every shipped weight/style and variable axis range, e.g. family=Roboto:ital,wdth,wght@0,75..100,100..900;1,75..100,100..900&display=swap.

    Does includeFiles return both woff2 and TTF?

    Yes. fontFiles comes from CSS2 and contains woff2 URLs with unicode ranges. ttfFiles comes from the download manifest. Both are capped by maxFilesPerFamily.

    Why is menu in subsets?

    It is a synthetic subset Google adds to every family; languageSubsets removes it. About 110 menu-only families have no unicode-range/coverage data.

    Is isBrandFont a generic brand filter?

    No. In the current catalog it is true only for the Noto families and equals isNoto. Google Sans and TikTok Sans are false.

    Are these fonts free to use?

    Yes. The catalog currently contains about 1,919 SIL Open Font License families, 35 Apache-2.0 families, and 5 Ubuntu Font Licence families. Use includeLicense for exact per-family data.

    What does the license enrichment cost?

    One to three cookieless requests per family. It is off by default; enable includeLicense and/or includeFiles when you need those fields. Raw API calls that omit both keys keep the legacy byFamily auto-enable for backward compatibility.

    Why is languages empty or missing?

    The main catalog's languages array is empty for all 1,959 families upstream. The actor therefore does not publish it from the catalog. includeLicense enrichment fetches the per-family endpoint (one request per family) and writes languages there; even then, a few families (Noto Color Emoji, Noto Emoji, Allkin) have no language list.

    Why are popularity and trending not 1..N?

    They are sparse snapshot ranks from an opaque upstream universe, not catalog positions. In the current snapshot popularity has gaps and values above 2,000, and trending has hundreds of gaps and values above 2,400; both change day to day. Use defaultSort or name when you need deterministic ordering, and treat the ranks as relative signals only.

    Why do some file lists stop at 200?

    maxFilesPerFamily defaults to 200. Large CJK families emit hundreds of CSS2 blocks (M PLUS 1p: 882), so the list is capped and filesTruncated / ttfFilesTruncated is set while fileCount / ttfFileCount report the full total. Raise the cap to 1,000 to keep more. CSS2 output is also user-agent dependent; the actor uses Chrome with a Safari retry so woff2 is returned where possible.

    How does icons mode work?

    It fetches https://fonts.google.com/metadata/icons?incomplete=true once and emits one record per icon with codepoint, version, popularity, categories, tags, sizes, and supported/unsupported Material families. It does not fetch font-family metadata and does not make per-icon requests. Because the endpoint has about 6,139 icons and maxItems is capped at 5,000, use search/sortBy to target subsets.

    How fresh is the data?

    Live — the actor fetches the current metadata document on every run, so new families and updates appear as soon as Google publishes them.

    What are the known upstream limits?

    The metadata endpoints (including metadata/icons) are undocumented and have no SLA; popularity/trending are sparse ranks with gaps; main metadata languages is always empty (the per-family endpoint is used instead); isBrandFont exactly equals isNoto in the current catalog and is not a generic brand flag; dateAdded is the catalog date while sourceDateAdded is the source-repository date; CSS2 output is user-agent and CJK-payload dependent; and the upstream size field is not a downloadable file size, so it is not published.

    Is this affiliated with Google?

    No. This is an independent, third-party actor that reads Google Fonts' publicly available metadata and is not affiliated with or endorsed by Google.

    Limits and notes

    Optional license & attribution fields (includeLicense)

    License enrichment uses three cookieless sources in order: the per-family metadata endpoint, METADATA.pb in the google/fonts repository, then the download manifest. The main catalog's languages array is always empty upstream, so languages is populated only by the per-family enrichment path.

    Field Description
    license ofl, apache2, or ufl
    licenseName Human-readable license name
    licenseUrl Official license URL
    licenseSource Where the license came from: per_family, metadata_pb, or download_list
    copyright Unique copyright line(s)
    sourceRepositoryUrl Upstream source repository from METADATA.pb
    sourceCommit Source repository commit when published
    sourceDateAdded Source-repository date; distinct from catalog dateAdded
    languages Language codes from the per-family endpoint
    languageCount Number of language codes
    unicodeCoverage Subset -> decimal codepoint ranges
    description Family description as plain text
    minisiteUrl Family minisite when published

    Optional self-hosting fields (includeFiles)

    Field Description
    fontFiles [{url, format, style, weight, stretch, unicodeRange, subset}] parsed from CSS2
    fileCount Total CSS2 @font-face files before capping
    filesTruncated true when fileCount exceeded maxFilesPerFamily
    ttfFiles [{url, filename, format: "ttf"}] from the download manifest
    ttfFileCount Total TTF files before capping
    ttfFilesTruncated true when the TTF list exceeded maxFilesPerFamily

    CSS2 is user-agent dependent. The actor requests woff2 with a modern Chrome UA and retries once with a Safari UA when Chrome is served TTF only (for example Chiron Sung HK). Legacy user agents would receive TTF/WOFF without unicode ranges, so the actor does not expose a user-agent input. HTTP errors are surfaced as css_failed error records instead of crashing the run.

    CJK families can be large: M PLUS 1p emits 882 CSS2 blocks, Noto Sans SC 101, Noto Sans JP 124, Noto Sans HK 109, and Chiron Sung HK 236. maxFilesPerFamily defaults to 200 and is capped at 1,000; when a family exceeds the cap, filesTruncated / ttfFilesTruncated is true and fileCount / ttfFileCount still report the uncapped total.
