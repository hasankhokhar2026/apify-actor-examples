BuiltIn Tech Company Directory & Hiring Signal Scraper

Browse BuiltIn.com's US tech-company directory across multiple cities by industry, technology, size and work arrangement; search companies by name or fetch profiles. Get headcount, tech stack, offices, benefits and hiring signals.

BuiltIn Tech Company Directory & Hiring Signal Scraper is an Apify Actor published by Nimbryxo Studio. It accepts 20 input fields, and mode is required. Its build declares a results dataset with 1 view. Runs happen on Apify, where the Store page lists the current price.

Input schema

Input fields, types, required flags, descriptions, defaults, and prefills come from the published definition. Prefill examples are distinct from defaults.

FieldTypeRequiredDescription
modestringrequiredWhat to fetch. `browse` walks the BuiltIn company directory with the filters below. `search` looks companies up by name. `byCompany` fetches specific companies by name, slug or BuiltIn URL.
searchQueriesarrayoptionalCompany names or partial names to search for, e.g. `stripe`, `openai`, `data dog`. Browse-only filters are ignored in search mode with a warning. Each query returns up to 50 matching companies before `maxItems` is applied.
companyUrlsarrayoptionalBuiltIn company URLs (e.g. `https://builtin.com/company/stripe`), slugs (`stripe`) or exact company names (`Stripe`). Names are resolved through BuiltIn's company search; only an exact slug or exact name match is accepted. Unresolved inputs are emitted as error rows with `input` and `error` fields.

FieldTypeRequiredDescription
modestringrequiredWhat to fetch. `browse` walks the BuiltIn company directory with the filters below. `search` looks companies up by name. `byCompany` fetches specific companies by name, slug or BuiltIn URL.
searchQueriesarrayoptionalCompany names or partial names to search for, e.g. `stripe`, `openai`, `data dog`. Browse-only filters are ignored in search mode with a warning. Each query returns up to 50 matching companies before `maxItems` is applied.
companyUrlsarrayoptionalBuiltIn company URLs (e.g. `https://builtin.com/company/stripe`), slugs (`stripe`) or exact company names (`Stripe`). Names are resolved through BuiltIn's company search; only an exact slug or exact name match is accepted. Unresolved inputs are emitted as error rows with `input` and `error` fields.
startUrlsarrayoptionalOptional BuiltIn URLs to process instead of the mode routes. Accepts requestListSources shapes: plain strings or objects with a `url` field, e.g. `{ "url": "https://builtin.com/companies?city=Chicago" }`. Directory URLs (`/companies...`) are paginated and results are deduplicated; company profile URLs (`/company/...`) are enriched directly. Other hosts and paths are emitted as error rows. `?page=` in a start URL is used as the first page.
locationsarrayoptionalBrowse one or more US city/metro markets. BuiltIn does not OR repeated city parameters, so the actor requests each market separately and unions/deduplicates the results; records include `searchLocation` and `matchedLocations`. Accepts the same aliases as `location` (e.g. `chicago`, `austin`, `new-york-city`) and their display titles. Overrides `location` when it contains a valid market. Browse mode only.
locationstringoptionalUS city or metro market to browse. Used only when `locations` is empty; browse mode only, while search/byCompany ignore it with a warning. `All US` searches every US market. Legacy values `national` and an empty value also mean all US.
industrystringoptionalFilter companies by BuiltIn industry. Browse mode only; search/byCompany ignore it with a warning.
technologystringoptionalFilter companies by a technology they publish on BuiltIn. Browse mode only; search/byCompany ignore it with a warning.
companySizestringoptionalFilter companies by employee-count band. Browse mode only; search/byCompany ignore it with a warning.
officeTypestringoptionalFilter by work arrangement. Browse mode only; search/byCompany ignore it with a warning. `remote` means fully remote companies; `hybrid` and `on-site` match the company's published office model. Values such as `On-Site`, `On Site` and `onsite` are normalized to `OnSite`. Companies with no published work model are excluded when this filter is set.
hiringOnlybooleanoptionalOnly return companies with at least one open job on BuiltIn. Companies without a published hiring signal are excluded when this filter is set. Browse mode only; search/byCompany ignore it with a warning.
remoteJobsOnlybooleanoptionalOnly return companies that currently list remote jobs on BuiltIn. Browse mode only; search/byCompany ignore it with a warning.
minEmployeesintegeroptionalDrop companies whose published employee count is below this value. Companies without a published count are kept. If `minEmployees` is greater than `maxEmployees`, the actor stops with a clear status message instead of returning bad data.
maxEmployeesintegeroptionalDrop companies whose published employee count is above this value. Companies without a published count are kept. If `minEmployees` is greater than `maxEmployees`, the actor stops with a clear status message instead of returning bad data.
includeDetailsbooleanoptionalFetch each company's full BuiltIn record for its tech stack, offices, headquarters, founding year, website and benefits count. If a detail record is missing or has no tech stack, the actor falls back to the company profile page. Turn off for the fastest listing-only run.
includeProfilebooleanoptionalAlso read each company profile for recent jobs, typical on-site time and product/tech headcount. Adds one request per company.
includeJobCardsbooleanoptionalRead each company's public `/company/{slug}/jobs` page and attach up to 20 recent job cards (`jobCards`) with job ID, title, approximate posted age, location and workplace type. This is a recent-page sample, not the company's complete job board. Adds one request per company.
postedWithinDaysintegeroptionalKeep only recent job cards whose published relative age is within this many days. Ages are approximate (`postedAgeDaysApprox`); cards with no age or an open-ended age such as `30+ Days Ago` are excluded because freshness cannot be confirmed. Setting this enables `includeJobCards` automatically.
includeBenefitsbooleanoptionalAlso read each company's benefits page and return the full list of published perks. Adds one request per company.
maxItemsintegeroptionalHard cap on company records returned; the maximum remains 10,000 per run. Large runs with includeDetails on are slow because each company needs a detail request; use includeDetails false for bulk listing. For a directory larger than 10,000, run filtered shards (for example one market or industry per run) and merge datasets by companyId/slug. The actor warns if its page safety cap is reached before maxItems.

BuiltIn Tech Company Directory & Hiring Signal Scraper

BuiltIn is a US tech-career and company-research platform where employers publish their headcount, industries, office locations, technology stack, benefits and open roles. This actor turns that public directory into structured company records: browse by city, industry, technology, size and work arrangement, search companies by name, or fetch specific profiles. No account, cookie or proxy setup is needed.

What this actor does

  • Three modes: browse the US company directory, search companies by name, or fetch specific companies by name, slug or BuiltIn URL
  • Multi-city browse: pass one or more markets in locations; the actor requests each market separately, unions the results and deduplicates companies by BuiltIn ID/slug
  • Start URLs: pass BuiltIn directory or company-profile URLs directly (plain strings or request-list-source objects) when you already know the pages you want
  • Directory filters: 79 US city/metro markets, 103 industries, 213 technologies, six employee-size bands, hybrid/on-site/fully-remote work arrangements, and companies with open jobs or open remote jobs
  • Company intelligence: headcount, industry tags, headquarters, every published office, founding year, website, logo, cover image, full description and tagline
  • Tech and benefits: category-tagged technology stack plus the number of published benefits, with optional full benefit lists
  • Hiring signals: whether the company is hiring, total open roles, open roles by category, and optional recent job listings
  • Job freshness: optionally read each company's public jobs page for up to 20 recent job cards with job ID, title, approximate posted age, location and workplace type; filter them with postedWithinDays
  • Honest signals: flags when category counts do not add up to the published total, when a listing description is used, when recent jobs are only a sample, and when job ages are approximate or open-ended
  • Clean records: empty fields are omitted, not sent as null

Output per company

  • companyId - BuiltIn's internal company ID
  • name - company name
  • slug - BuiltIn profile slug
  • builtInUrl - canonical BuiltIn company profile URL
  • logoUrl - company logo image
  • coverImageUrl - company cover image
  • description - the company's published description

  • tagline - the company's one-line pitch
  • industries[] - BuiltIn industry tags
  • employeeCount - published employee count
  • localEmployees - BuiltIn's published local-employee count when a location filter is used; omitted otherwise
  • searchLocation - the market whose browse request produced the record (city/metro title)
  • matchedLocations[] - every requested market in which the company appeared; a single record is emitted per company
  • officeCount - number of published offices
  • offices[] - office locations as readable strings
  • officeLocations[] - structured offices with city, state, country, postalCode, streetAddress, isHeadquarters
  • headquarters - headquarters location
  • headquartersCity, headquartersState, headquartersCountry, headquartersPostalCode
  • websiteUrl - the company's official website
  • founded - founding year
  • workModel - OnSite, Hybrid or Remote
  • hybridDetails - published on-site pattern (onsiteType, onsiteValue)
  • workplacePolicy - the company's published workplace-policy text
  • introHeader - the profile intro heading, when published
  • whyWorkWithUs - the company's published recruiting pitch
  • techStack[] - technologies with name, category and iconUrl
  • techStackByCategory - technologies grouped by category
  • techStackSize - number of published technologies
  • extraTechnologies[] - additional technologies with name and category
  • benefitsCount - number of benefits shown in the directory listing
  • perksCount - number of benefits recorded on the company profile
  • perksOverview - the company's published benefits summary
  • perks[] - full published benefit list (with includeBenefits)
  • perkCategories[] - benefit category headings (with includeBenefits)
  • isHiring - whether the company currently has open roles
  • openJobsCount - total open roles shown by BuiltIn; omitted if BuiltIn does not publish a total (counts are never inferred from categories)
  • openJobsByCategory - open roles grouped by category
  • openJobsByCategoryIsPartial - true when the category counts are published but do not add up to openJobsCount

  • jobCardsIsRecentSample - true because jobCards is the recent page sample, not a claim that the full job board was scraped

  • productAndTechEmployeeCount - product and technology headcount, when published (with includeProfile)
  • typicalTimeOnSite - published on-site expectation (with includeProfile)
  • lastUpdated - BuiltIn's last-updated timestamp
  • sourceUrl - the listing or profile page the record was read from
  • recordType - company for company records, error for unresolved byCompany inputs or invalid start URLs
  • scrapedAt - ISO 8601 scrape timestamp

Error rows (mode=byCompany and startUrls)

When a companyUrls input cannot be matched to an exact BuiltIn slug or name, the actor emits an error row with input, error, recordType: "error" and scrapedAt instead of returning a different company. The same happens for startUrls entries that are not BuiltIn directory or company-profile URLs.

Input

Field Type Default Description
mode string browse browse walks the directory, search looks companies up by name, byCompany fetches specific companies. startUrls takes precedence when set.
searchQueries array [] Company names or partial names to search for (mode=search). Browse-only filters are ignored in search mode with a warning.
companyUrls array [] Exact company URLs, slugs or names to fetch (mode=byCompany). Unresolved inputs become error rows.
startUrls array [] BuiltIn directory (/companies...) or company-profile (/company/...) URLs. Accepts plain strings or request-list-source objects with a url field. Directory URLs are paginated; ?page= is used as the first page. Other hosts/paths become error rows.
locations array [] Browse one or more markets. Each market is requested separately and results are unioned/deduplicated. Accepts the same aliases as location plus display titles. Overrides location when it contains a valid market. Browse only.
location string All US Browse only. Single US city/metro market used when locations is empty. national and an empty value also mean all US. Ignored with a warning in search/byCompany.
industry string All Browse only. BuiltIn industry filter. Ignored with a warning in search/byCompany.
technology string All Browse only. Technology filter. Ignored with a warning in search/byCompany.
companySize string All Browse only. Employee-count band: 1-10, 11-50, 51-200, 201-500, 501-1000 or 1000. Ignored with a warning in search/byCompany.
officeType string All Browse only. hybrid, on-site or remote. Values such as On-Site, On Site and onsite normalize to OnSite; companies without a published work model are excluded when this filter is set. Ignored with a warning in search/byCompany.
hiringOnly boolean false Browse only. Only companies with at least one open job; companies without a hiring signal are excluded. Ignored with a warning in search/byCompany.
remoteJobsOnly boolean false Browse only. Only companies currently listing remote jobs. Ignored with a warning in search/byCompany.
minEmployees integer - Drop companies below this published headcount. Companies without a count are kept. An inverted range (minEmployees > maxEmployees) stops the run with a clear status message.
maxEmployees integer - Drop companies above this published headcount. Companies without a count are kept. An inverted range (minEmployees > maxEmployees) stops the run with a clear status message.
includeDetails boolean true Fetch each company's full BuiltIn record for tech stack, offices, headquarters, founding year, website and benefits count. Falls back to the profile page when detail is missing or has no tech stack.
includeProfile boolean false Also read each profile for recent jobs, on-site expectations and product/tech headcount.
includeJobCards boolean false Read each company's public /company/{slug}/jobs page and attach up to 20 recent job cards with approximate posted age. This is a recent-page sample, not the complete job board. Adds one request per company.
postedWithinDays integer - Keep only job cards whose published relative age is within this many days (1-3650). Ages are approximate; cards with an unknown or open-ended age such as 30+ Days Ago are excluded. Enables includeJobCards automatically.
includeBenefits boolean false Read each company's benefits page and return the full benefit list.
maxItems integer 100 Hard cap on company records (1-10,000). Large runs with includeDetails on are slow; use false for bulk listing. For more than 10,000 companies, use filtered shards and merge by companyId/slug (see the FAQ).

FAQ

Do I need an account, cookie or API key? No. The directory, company profiles and search results used here are public. No login or key is required.

Do I need to configure a proxy? No. The actor connects to BuiltIn automatically. Just fill in the input and run it.

What is the difference between browse, search, byCompany and startUrls? browse walks the directory and applies the filters. search matches company names and returns the closest matches. byCompany accepts only an exact slug or exact name match; unresolved inputs become error rows rather than a different company. startUrls skips the mode routes and reads the BuiltIn directory/profile URLs you supply.

Can I browse several cities in one run? Yes. Put the markets in locations. BuiltIn does not OR repeated city parameters, so the actor makes a separate request per market, unions the companies and deduplicates by BuiltIn ID/slug. location remains the single-market fallback when locations is empty.

Why is openJobsByCategoryIsPartial set? BuiltIn sometimes shows a total open-roles count that differs from the sum of the category links (for example, the total counts roles in categories the page does not list). The actor reports the published total as-is and sets the flag instead of inventing a new total.

Why is descriptionIsTruncated set? The directory listing shows a shorter description than the full company profile. When includeDetails is off, or the profile has no longer description, the actor keeps the listing copy and flags it. A full detail/profile description clears the flag.

What does recentJobsSampleSize mean? It is the number of job cards read from the profile, not the company's total number of open roles. Use openJobsCount for the published total.

What is the difference between recentJobs and jobCards? recentJobs is a small sample read from the company profile with includeProfile. jobCards is read from the public /company/{slug}/jobs page with includeJobCards and includes the job's relative posted age. Both are samples; neither claims to be the complete job board.

Are job posting dates exact? No. BuiltIn publishes relative labels such as 15 Hours Ago, 2 Days Ago, One Month Ago and 30+ Days Ago. The actor stores that label as postedAge, derives postedAgeDaysApprox, and sets postedAgeIsApproximate: true. It does not invent an exact postedAt timestamp. Open-ended labels keep postedAgeIsMinimum: true, and postedWithinDays excludes cards whose freshness cannot be confirmed.

Why do some companies have no employeeCount, founded or headquarters? Those values are self-reported by companies. If a company has not published a value, the field is omitted rather than guessed.

Why is benefitsCount different from perksCount? benefitsCount is the count shown in the directory listing. perksCount is the count recorded on the company profile. They can differ because BuiltIn maintains both views.

Why do some companies have no tech stack? Companies choose what to publish. Companies with no published stack omit techStack and techStackSize.

Why are recentJobs, jobCards or perks missing? recentJobs requires includeProfile (or a search/company lookup). jobCards requires includeJobCards (or postedWithinDays, which enables it). perks requires includeBenefits. Each option adds one request per company.

How many companies can one run return? maxItems supports up to 10,000 records per run. BuiltIn serves 20 directory companies per page, and the source directory is larger than 10,000 companies. The cap is intentionally not raised because larger single runs mean thousands of sequential listing requests and a higher chance of an early block. The actor uses a page safety cap derived from maxItems plus a 50-page scan buffer, with a hard safety ceiling of 5,000 pages, and warns when it stops because of maxItems or the page cap. With multiple locations, the page cap applies per market.

How do I get more than 10,000 companies? Use sharded runs for more than 10,000 companies: run several smaller jobs and merge the datasets by companyId (or slug). Each shard can use the full 10,000 cap:

{ "mode": "browse", "locations": ["chicago", "austin"], "industry": "fintech", "maxItems": 10000 }

{ "mode": "browse", "industry": "software", "technology": "python", "includeDetails": false, "maxItems": 10000 }

Shard by locations, industry, technology or a startUrls list. Keep includeDetails: false for the fastest listing-only pass, and deduplicate after merging because a company can appear in more than one market or filter. This is a supported workaround, not a claim that one run can enumerate the whole directory.

Does the actor rely on the ?page= parameter? Yes. BuiltIn's public directory HTML exposes only 20 companies per page and paginates with ?page=N, so browse mode uses that parameter. BuiltIn's robots.txt for User-agent: * contains Disallow: *?page= (only /jobs*?page= is explicitly allowed), so this is a residual policy risk, not a robots-safe enumeration path. The actor stops a source on 403/429 and reports partial counts in the status message; it does not use translation proxies, mirror hosts, or a robots workaround.

The GraphQL filterCompanies endpoint was tested as an alternative on 2026-11-06. A single request works, but page=1 and page=2 overlapped by 16 IDs out of 100 and left gaps, perPage=5000 took about 53 seconds, and perPage=10000 failed. Because paginated enumeration is not reliable, the actor does not use it. The recent-job-card path reads /company/{slug}/jobs without a ?page= query. If robots compliance is mandatory for your use case, keep each run narrow (a market or industry shard with a low maxItems) and verify the current robots.txt before running.

How current is the data? Every run reads BuiltIn live. Company profiles are maintained by the companies themselves, so values reflect what they have published at run time.

What happens if a byCompany name does not match exactly? The actor emits an error row with input and error instead of guessing. Paste the company's BuiltIn URL if its display name differs from its slug.

Does officeType need extra requests?

Yes. The work model is published on the company detail/profile, not the listing card. When officeType is set and includeDetails is off, the actor enables detail enrichment automatically and says so in the status message. Size bands are applied client-side from the published employee count, so the actor does not use BuiltIn's robots-disallowed /companies/size/... URLs.

Can I use the browse filters with search or byCompany? No. locations, location, industry, technology, companySize, officeType, hiringOnly and remoteJobsOnly apply only to browse; in the other modes they are ignored with a clear warning in the status message. For startUrls, encode BuiltIn-side filters in the URL itself; the local minEmployees, maxEmployees, officeType and hiringOnly checks still apply to directory URLs.

Is this affiliated with BuiltIn? No. This is an independent, third-party actor that reads BuiltIn's public company directory and profiles. It is not affiliated with or endorsed by BuiltIn.
