    StubHub Live Event & Venue Finder by Category is an Apify Actor published by Nimbryxo Studio. It accepts 14 input fields, and mode is required. Each result can carry up to 10 declared fields, including eventTitle, eventDate, eventDateIso, venueName, venueCity and countryCode. It costs $0.99 per 1,000 results on Apify's Free plan and $0.49 on the Business plan.

    What it does

    The full README, with every mode, example and answer the publisher documents, is on the Apify Store page. Its sections: “What this actor does”, “Output per event”, “Input”, “Prices”, “Search pagination and date windows” and “City explore”.

    What it costs

    StubHub Live Event & Venue Finder by Category uses pay-per-event pricing: a fee for each result saved to the dataset, plus a start fee per run. Paid Apify plans pay less per result. The start fee is charged once per GB of run memory (at least once); the default run uses 4 GB, so a run starts with 4 start events, as the run totals include. You also pay Apify platform usage (compute and proxy) for the run, which these totals do not include.

    Input reference

    All 14 fields of the published input schema, in the publisher's order. Required fields are marked. Download the input schema as JSON.

    Input fields in the published schema
    FieldTypeDescription
    modeModestring requiredSearch by keyword, explore events near a city, or use legacy category browse (mapped to keyword search).Default "search"; Allowed search, byCity, byCategory
    searchQuerySearch querystringArtist, team, venue or event name. Required for mode=search; optional refinement for mode=byCategory; ignored in mode=byCity.Default ""; Example "Taylor Swift"
    cityCitystringMetro area to explore (mode=byCity). Each option has verified coordinates and is searched within the radius below.Default "New York"; Allowed New York, Los Angeles, Chicago, Houston, Phoenix, Philadelphia, San Antonio, San Diego and 28 more
    browseCategoryBrowse categorystringLimit city explore to one top-level category. In search mode this is only a price-enrichment hint; StubHub search itself is not category-filtered.Default "all"; Allowed all, sports, concerts, theater, festivals
    radiusKmRadius around city (km)integerDistance from the selected city centre for mode=byCity.Default 50; Allowed 1 to 500
    categoryCategory (legacy browse)stringRequired for mode=byCategory; optional search hint for mode=search. StubHub search does not guarantee server-side category filtering, so this changes the query context and price fallback, not a strict filter.Default ""; Example "260542"; Allowed , 6453, 6456, 5084, 4871, 5062, 263024, 1012 and 29 more
    countryCountrystringKeep events from one country. Applied client-side: search records use StubHub's country code, city records use the country parsed from the venue location. The request cc value is only a locale hint, not a server filter. Records whose country cannot be resolved are not excluded.Default ""; Allowed , US, CA, GB, DE, ES, FR, IT and 33 more
    dateFromEvent date fromstringEarliest event date, as YYYY-MM-DD or a full ISO 8601 datetime. Used server-side for pagination windows and enforced again on every record.Default ""
    dateToEvent date tostringLatest event date, as YYYY-MM-DD or a full ISO 8601 datetime. Used server-side for pagination windows and enforced again on every record.Default ""
    sortSortstringSearch result order. City explore is always returned in event-date order.Default "relevance"; Allowed relevance, date
    includePricesInclude from-pricebooleanFetch the lowest current from-price for active US/Canada listings. Adds one batched request per 20 events; price fields are omitted when StubHub has no price.Default true; Example false
    maxItemsMax itemsintegerHard cap on emitted records. Search paginates and splits date windows to go beyond StubHub's per-page limit; city explore paginates until exhausted.Default 20; Example 3; Allowed 1 to 5000
    confirmedDateOnlyConfirmed dates onlybooleanOnly include events whose date is confirmed (excludes TBD-date events).Default false
    activeListingsOnlyActive listings onlybooleanOnly include search records that currently have active ticket listings. City explore does not expose a reliable availability flag, so city records pass through.Default false
