    StubHub Live Event & Venue Finder by Category is an Apify Actor published by Nimbryxo Studio. It accepts 14 input fields, and mode is required. Each result can carry up to 10 declared fields, including eventTitle, eventDate, eventDateIso, venueName, venueCity and countryCode. It costs $0.99 per 1,000 results on Apify's Free plan and $0.49 on the Business plan.

    What it does

    StubHub lists thousands of sports, concert, theater and festival events at any time. This actor turns the public search and metro-explore data of the StubHub US/Canada marketplace (www.stubhub.com and www.stubhub.ca) into clean event records: title, date, venue, city, country, category, availability flags, an optional lowest from-price, and a direct event link. It runs with plain HTTP, no login, no cookies, no proxy setup, and no browser.

    What this actor does

    • Search by keyword — artist, team, venue or event name. Paginates past the first page and splits large result sets into date windows to get closer to StubHub's full index.
    • Explore by city — 36 verified metro areas across North America, Europe, Australia and Asia, with a 1-500 km radius, top-level category filter, and date range.
    • Filter by date, country, confirmed-date-only, and active-listings-only.
    • Optional from-price — lowest current price for active US/Canada listings, in USD or CAD.
    • Omit-empty output — fields StubHub does not provide for an event are left out, never set to null, "", "N/A" or another sentinel.

    Questions

    Do I need a StubHub account, cookies or a proxy?

    No. The actor uses public endpoints and plain HTTP.

    Why is there no ticket price for some events?

    StubHub only returns a from-price when the marketplace has an active, quotable listing. Far-future, deferred, inactive and non-US/Canada records are not price-requested or return no price; the fields are then omitted.

    Can I get more than 500 results for one artist?

    Usually yes, because the actor splits large queries into date windows and deduplicates. A single window above StubHub's cap is the residual limit.

    Can I get every event in a city?

    City explore paginates the public metro feed. The feed's reported total can include grouped/venue entries, so the returned row count may be slightly lower.

    Why does hasActiveListings not appear on city records?

    StubHub's Explore feed reports false for every event we probed, including events with known inventory, so the field is not reliable there and is omitted.

    Does this actor cover the UK, Germany or Ireland?

    Not currently. This revamp targets the US/Canada marketplace (.com/.ca). Country hosts have a different address/venue/listing surface and are tracked as a future scope gap.

    Is this affiliated with StubHub?

    No. This is an independent data extraction tool.

    Limits and notes

    Prices

    • Prices come from StubHub's public EventPrices endpoint, requested in batches of 20 with browser TLS impersonation.
    • US and Canada records, plus records whose country cannot be resolved, are requested. www.stubhub.com prices are USD; www.stubhub.ca prices are CAD.
    • Search records without active listings are not requested. City explore has no reliable availability flag, so its records are requested and unpriced ones stay unpriced.
    • The price is a lowest "from" price, not a seat quote. Far-future events, deferred prices and events without inventory simply omit priceFrom/priceCurrency.
    • Pricing adds requests and time; turn includePrices off for the fastest, cheapest run.

    Search pagination and date windows

    StubHub's search JSON returns 20 items per page and stops after roughly 500 rows even when it reports a higher total. This actor:

    1. Paginates page by page.
    2. If a query reports more rows than the page cap, splits the requested date range in half and repeats, deduplicating by event ID.
    3. Stops on maxItems, an empty page, or source exhaustion.

    In live probes this recovered 629 of 634 unique Taylor Swift events. A single day/window that contains more than the cap can still under-deliver; narrow the date range or add a category hint to split further. Relevance ordering across multiple date windows is approximate; date ordering is exact within each window.

    City explore

    City explore uses StubHub's public Explore endpoint with Size=1000. It supports 36 verified metros and top-level categories. Explore reports a total that can include grouped/venue entries, so row counts can be slightly below the displayed total. Empty pages with missing total or remaining are retried and skipped rather than treated as the end; pagination stops on a positive remaining: 0, two consecutive empty pages after retries, maxItems, or the hard page cap. This recovers rows after transient empty pages, including a 996 -> empty -> 587 sequence observed for New York.

    Limitations

    • Event-page scope is the US/Canada marketplace (.com/.ca). Search on .com still returns global inventory, but event-page/listing enrichment is scoped to .com/.ca. Country hosts such as www.stubhub.co.uk, www.stubhub.de and www.stubhub.ie expose address, venue and listing-level data through __INITIAL_STATE__ and /bfx/api/catalog/events/v3. That is a separate market surface and is not implemented here; it is a documented future/scope gap, not a claim that the data is unreachable.
    • No ticket-level inventory on .com/.ca. These event pages return HTTP 403 to automated HTTP clients behind DataDome. This actor does not fetch them, so it cannot provide section, row, seat, quantity, listing count or deal score there. It does not fabricate them.
    • No venue address, map, seating chart, lineup, parking or set times on .com/.ca. Those live on the blocked event pages. Country hosts are a separate, unimplemented surface.
    • No URL/ID lookup mode. Searching a raw event ID returned no matches in probes, and slug-derived lookup was inconsistent. Use the event title or performer name.
    • category is a hint, not a guaranteed filter. StubHub search ignores leaf category IDs as a strict server-side filter. Use mode=byCity + browseCategory when you need a true top-level category browse.
    • activeListingsOnly applies to search records. Explore's hasActiveListings flag was false for every event in a 990-event probe, so city records omit it and the filter passes city records through.
    • City sort is always date order. Explore's relevance sort returned HTTP 500 in probes.
    • Country filtering is client-side. Search filters on StubHub's countryCode field; city records use the country parsed from the venue location. The request cc hint is a locale value and did not change result sets in probes. Events whose country cannot be resolved are not excluded.
    • Date range defaults. Search defaults to today through five years ahead; city explore defaults to today through 90 days ahead. Set dateFrom/dateTo for other horizons. Past events are not fetched.
    • Event price currency is marketplace-based. Only USD and CAD are emitted.
