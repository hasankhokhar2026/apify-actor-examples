Pinterest Pins, Profiles, Boards & Idea Topics Scraper

Collect public Pinterest Pins, creator profiles, boards, board sections, idea topics, search results, and comments in one cookieless actor. Point it at a keyword, a username, a board or section link, an idea-topic page, a numeric Pin, or a batch of mixed public links and it returns the matching rows with real media, creator, board, SEO, commerce, and engagement fields.

No Pinterest login, cookie, API key, or user-supplied proxy is required.

What this actor does

  • Searches Pins, video Pins, people, and boards.
  • Reads Pin details and public comments/activity by numeric Pin URL or ID.
  • Reads public profiles, a creator's Pins, and a creator's boards.
  • Reads board details, board Pins, board sections, and Pins inside a section.
  • Reads idea-topic metadata and, optionally, the Pins shown on the topic page.
  • Auto-routes mixed Pin, profile, board, section, idea, and search links.
  • Applies filters for minimum saves, minimum creator followers, verified accounts, outbound links, image-only results, promoted Pins, and shoppable Pins.
  • Pushes rows as they are collected and omits fields Pinterest never published.

Modes

Mode What it returns
auto Routes mixed public Pinterest links to the matching collector.
pinDetail One detailed Pin row per numeric Pin URL or ID.
comments Public comment and activity rows for numeric Pins.
searchPins Pins matching search phrases.
searchVideos Video Pins from Pinterest's native video search scope.
searchUsers Public profile rows from people search.
searchBoards Public board rows from board search.
userProfile Public profile identity, counts, websites, and flags.
userPins Pins in a creator's public created-Pins feed.
userBoards Boards owned by a public creator.
boardDetail Public board metadata.
boardPins Pins inside a board, or inside one board section when given a section URL.
boardSections Sections inside a board.
ideas Idea-topic metadata, plus topic Pins when includeIdeaPins is on.

Legacy task inputs are still accepted in code: search maps to searchPins, urls maps to pinUrls, limit maps to maxComments, and queries maps to keywords. Cookie fields are no longer used; public Pinterest data needs no cookies.

Use cases

  • Niche content research: pull high-save, verified-creator Pins for a topic.
  • Creator audits: profile a list of usernames for follower and Pin counts.
  • Board and section snapshots: export a large board or one section.
  • Idea-topic monitoring: track a curated topic and its current Pins.
  • Mixed-link batch processing: route a list of assorted Pinterest URLs in one run.

FAQ and limits

Do I need Pinterest cookies or a login? No. Every shipped mode reads public data. Cookie inputs from old saved tasks are ignored with a log line.

Why is pinUrl missing on some Pin rows? Recent signed-out search, board, and idea feeds return opaque e1_... IDs that Pinterest's detail endpoint cannot open. Those rows are still real list data; the actor keeps pinId and adds idIsEncrypted=true and detailAvailable=false instead of writing a broken URL.

Why do search rows not show saves or comment counts? Pinterest does not publish those counters on most signed-out search cards. The actor emits only counters the source actually contains and never invents zeroes.

Does relatedPins still work? No. Pinterest serves the related-closeup feed on the workstation but blocks it by ASN from Apify cloud exits, so the mode is not advertised or shown in the input schema. Old saved tasks that still send mode=relatedPins finish with a status message explaining the limit instead of returning a silent empty result. Use searchPins, boardPins, or ideas for discovery.

What about the root /ideas/ feed? Pinterest requires a numeric interest ID for the topic feed. Use a topic URL such as /ideas/beauty/935541271955/; the root page alone is not supported.

Can I filter by price or domain on the server? Those unpublished search options are not exposed because they are ignored or require a token. Use commerceOnly and the client-side filters that Pinterest's public data actually supports.

Are comment replies included? The actor returns the public top-level comment and activity rows Pinterest serves. Replies are not a separate shipped mode.

Will a proxy be selected automatically? Yes. The actor tries public traffic first, then Apify datacenter proxy, and honours an optional caller-supplied proxy. You never need to configure one.

How large a run can I do? maxItems supports up to 20,000 rows and the actor follows feed cursors with duplicate and cursor-loop guards. Output is still bounded by what Pinterest's public feed exposes.

Is this affiliated with Pinterest? No. It is an independent actor that reads public Pinterest pages and is not endorsed by Pinterest, Inc.
