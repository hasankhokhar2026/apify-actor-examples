    Twitter (X) Screenshot Generator is an Apify Actor published by Nimbryxo Studio. It accepts 17 input fields, none of them required at the top level. Each result can carry up to 59 declared fields, including type, targetUrl, captureMode, theme, status and code. It costs $0.99 per 1,000 results on Apify's Free plan and $0.49 on the Business plan.

    What it does

    Capture clean screenshots of public X posts, threads and profiles — no login, no cookies, no API key. Paste post links to get pixel-perfect post cards or a contiguous thread image, or profile links to get the profile header or the loaded profile preview. Choose dark, light or system theme, PNG/JPEG/WEBP output, and 1x–3x pixel density. Capture dark and light in one run, and optionally save a verifiable evidence pack (gzipped DOM snapshot + JSON manifest with SHA-256 hashes).

    What this actor does

    • Four capture modes: postCard (one post), thread (root post + contiguous same-author replies), profileHeader (header only) and fullProfilePage (the loaded profile preview)
    • Verified targets: the canonical post id and author handle are checked, so a short ID that resolves to another author is reported as wrong_author instead of a false success
    • Honest failure states: protected, deleted, missing and login-walled pages return typed, non-billable status rows
    • Clean captures: headers, sidebars, login prompts, the late "Continue to X" gate, sticky top bars, video player chrome and community notes are hidden automatically; the overlay hide is repeated after a 2.5s settle
    • Image control: PNG, JPEG or WEBP, quality setting for JPEG/WEBP, and real 1x/2x/3x pixel density with effectiveScale reported
    • Custom viewport: width and height from 320×240 up to 3840×2160
    • Optional details: post ID, URL, author handle, text snippet, and profile or author follower counts when X shows them
    • Both themes in one run: bothThemes captures dark and light versions with unique files and one row per theme
    • Evidence pack: includeEvidence saves a gzipped DOM snapshot and a JSON manifest to the key-value store, and reports screenshotSha256, domSnapshotSha256, evidenceKey and manifestKey on each row
    • Empty fields are omitted: never null, empty strings or empty arrays/objects.
    • Run summary: one runSummary row reports requested/captured/failed/billable counts, typed failure codes and dropped inputs
    • Empty fields are omitted

    Use cases

    • Social media reporting — embed clean post captures in decks, newsletters and blogs
    • Brand monitoring — archive screenshots of public posts as evidence
    • Community management — capture profile pages for creator or partner reviews
    • Research — build image datasets of public posts with consistent framing and theme
    • Content creation — generate post images for roundups without manual screenshotting
    • Legal and compliance — timestamped captures of public posts with source URLs, SHA-256 hashes and a DOM snapshot as an evidence trail

    Questions

    Can I screenshot private accounts or posts?

    No. Only public posts and profiles are accessible.

    What resolution are the screenshots?

    The viewport defaults to 1440×900 and is configurable from 320×240 up to 3840×2160. With 2x or 3x pixel density the saved image is two or three times larger on each side. The actual dimensions are always reported in width and height.

    What is the difference between the capture modes?

    postCard captures a single post as a clean card; profileHeader captures only the profile header (banner, avatar, name, bio, counts and tabs); fullProfilePage captures the loaded profile preview with its posts; thread captures the root post plus contiguous same-author replies. A post link captures a post card only in postCard mode — if profileHeader or fullProfilePage is selected, a post link captures that post's author profile instead.

    Does it support threads?

    Yes. Set captureMode to thread and the actor captures the root post plus the contiguous same-author replies as one image. Threads that hit a logged-out gate, a different author or maxThreadHeight are marked threadComplete: false with a truncation reason. The logged-out page only contains the articles X renders, so full unroll is not guaranteed.

    What happens if a post contains a video?

    The actor waits for the video to decode, pauses it, seeks to a representative frame, hides the player controls and applies a luma/poster guard against black frames before capturing.

    What gets hidden in a capture?

    The left navigation, headers, sidebars, login prompts, the late "Continue to X" gate, sticky top bars, video controls, empty fixed overlays and community notes are hidden automatically. The hide runs repeatedly after a 2.5s settle. Reply posts are hidden when Hide replies is on.

    Which image format should I use?

    PNG for lossless quality, JPEG for smaller files, WEBP for the smallest files. JPEG and WEBP use the quality setting.

    What if a link is invalid or the post was deleted?

    The row gets a typed code and a friendly status instead of a screenshot, marked billable: false. Protected, deleted, missing and login-walled pages are detected before the selector timeouts, and the run never crashes. The final runSummary row lists the counts and reasons.

    Can I capture dark and light in one run?

    Yes. Turn on Both themes and every target is captured twice, once dark and once light. Files include the theme in the name, so nothing is overwritten, and each theme gets its own dataset row and theme value. The run summary counts both captures and lists themes: ["dark", "light"].

    What is the evidence pack?

    With Include evidence pack on, each capture also writes evidence_<key>.html.gz (the rendered DOM, gzipped) and manifest_<key>.json (target, capture metadata, dimensions, SHA-256 hashes, and failure state when the capture failed) to the key-value store. Rows get screenshotSha256, domSnapshotSha256, evidenceKey and manifestKey. Evidence is typically ~7% of the screenshot size; failures still get a manifest even when no image was produced.

    How long do download links last?

    They follow your Apify key-value store retention (typically 7 days on the free tier). Copy the images to your own storage for permanent archival.

    Is this affiliated with X?

    No. This is a third-party actor that captures publicly visible pages.

    Limits and notes

    Limits

    • Public content only — protected accounts return a protected status row and cannot be captured.
    • Logged-out profiles show a loaded preview of roughly 5–10 posts (observed 5–10; it never grows with scrolling). fullProfilePage is that preview, not the infinite timeline, and rows set previewLimited: true. profileHeader is header-only by design.
    • Logged-out post pages render only the first ~4–10 replies. The See all the replies / Continue to X gate appears after scrolling; /replies is a 404/login redirect for guests, so deeper reply paging is not available.
    • Thread captures only contain the articles X renders in the logged-out DOM. A gate is reported as truncation only when its DOM position is before or inside the last captured part; a gate appended after the last article is the normal end of the preview. Non-author replies stop the contiguous block. Full unroll is not guaranteed.
    • maxThreadHeight is expressed in CSS pixels and is clamped automatically so the DPR-scaled image cannot exceed the 32,767 px screenshot ceiling (32,767 / 16,383 / 10,922 CSS px at 1x/2x/3x). Clipped threads report threadComplete: false with truncatedReason: max_height or dpr_height_limit.
    • Poll metadata is limited to the choices X renders or syndication binds (2–4 choices). Quote counts, places, full follower lists and sensitive flags are not available cookieless.
    • Community-note text is captured as text; the note is hidden from the image. The note id is included when the syndication/DOM link exposes it.
    • A bare short post ID can collide with an older post id. When the requested handle does not match the canonical author, the row fails with wrong_author rather than capturing the wrong post.
    • Metadata counts, poll and community-note fields are added only when X displays them.
    • Capture failures (for example a deleted post) produce a typed status row plus a runSummary, so a run is never silently empty or billed as a success.
    • Both themes doubles runtime, screenshots and dataset rows; files and evidence keys remain unique per theme.
    • Include evidence pack adds the DOM snapshot (gzipped, typically ~7% of the screenshot size) and a manifest per capture. The DOM is the post-hide rendered markup, not the raw HTTP response.
    • Evidence manifests are still written for failed captures (with failure.code, failure.message and failure.accessState) when the page is available; a crashed page may leave only the manifest.
