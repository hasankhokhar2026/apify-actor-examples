    Twitter (X) Screenshot Generator is an Apify Actor published by Nimbryxo Studio. It accepts 17 input fields, none of them required at the top level. Each result can carry up to 59 declared fields, including type, targetUrl, captureMode, theme, status and code. It costs $0.99 per 1,000 results on Apify's Free plan and $0.49 on the Business plan.

    What it does

    The full README, with every mode, example and answer the publisher documents, is on the Apify Store page. Its sections: “What this actor does”, “Output per screenshot”, “Input”, “Limits”, “Use cases” and “FAQ”.

    What you get

    The Actor saves one record per result to an Apify dataset. Its build declares 59 fields in 1 dataset view, and the README documents 3 more. Fields without a value can be left out of a record.

    What it costs

    Twitter (X) Screenshot Generator uses pay-per-event pricing: a fee for each result saved to the dataset, plus a start fee per run. Paid Apify plans pay less per result. The start fee is charged once per GB of run memory (at least once); the default run uses 4 GB, so a run starts with 4 start events, as the run totals include. You also pay Apify platform usage (compute and proxy) for the run, which these totals do not include.

    Input reference

    All 17 fields of the published input schema, in the publisher's order. No field is required at the top level, but the README can describe conditions. Download the input schema as JSON.

    Input fields in the published schema
    FieldTypeDescription
    postUrlsX post links, IDs or usernamesarrayPosts to capture as clean post cards. Paste x.com or twitter.com links, bare numeric post IDs, profile links or bare usernames. Any input works in every list.Default []; Example ["https://x.com/NASA/status/2107095768821576019"]
    tweetUrlsTweet links (alias)arrayAlias of X post links. Accepts tweet links, bare tweet IDs, profile links and bare usernames.Default []
    profileUrlsX profile links or usernamesarrayOptional. Profiles to capture. Paste profile links, bare usernames, post links or post IDs and the actor routes them to the right capture. Use capture mode to choose the header only or the loaded profile preview.Default []
    captureModeCapture modestringWhat to capture. Post links produce a single post card or a thread image; profile modes apply to profile links (and convert post links to the author profile).Default "postCard"; Allowed postCard, thread, profileHeader, fullProfilePage
    themeThemestringColor theme for the screenshot.Default "dark"; Allowed dark, light, system
    bothThemesBoth themesbooleanWhen on, every target is captured twice: once in dark and once in light. Files and rows are unique per theme (one screenshot row per theme) and the run summary reports both themes. Overrides the Theme selection.Default false
    includeEvidenceInclude evidence packbooleanSave a gzipped DOM snapshot and a JSON manifest to the key-value store for every capture, and add screenshotSha256, domSnapshotSha256, evidenceKey and manifestKey to each row. Failures still get a manifest with the typed failure state.Default false
    fullPageFull-page capturebooleanWhen on, the whole page is captured instead of just the post card or the visible profile header.Default false
    hideRepliesHide repliesbooleanHide reply posts so screenshots stay focused on original posts.Default true
    includeMetadataInclude post/profile detailsbooleanAdd details to each row: post id, post URL, author handle, text snippet and the author's follower, following and post counts for posts; username, display name, follower, following and post counts for profiles. Counts are only added when X shows them.Default false
    formatImage formatstringFile format of the saved screenshot. JPEG and WEBP support the quality setting; PNG is lossless.Default "png"; Allowed png, jpeg, webp
    qualityImage qualityintegerQuality for JPEG and WEBP output (1-100). Ignored for PNG.Default 90; Allowed 1 to 100
