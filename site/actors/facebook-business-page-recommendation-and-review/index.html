    Facebook Business Page Recommendation & Review Scraper is an Apify Actor published by Nimbryxo Studio. It accepts 17 input fields, none of them required at the top level. Each result can carry up to 30 declared fields, including recordType, pageName, authorName, isRecommended, text and createdAt. It costs $0.99 per 1,000 results on Apify's Free plan and $0.49 on the Business plan.

    What it does

    Extract Facebook business page recommendations and reviews from public pages without logging in. Paste a page URL, a numeric Page ID, or a username, and get review text, Recommended / Not Recommended status, author details, reactions, recommendation tags, comments and owner replies — plus a page-summary row with the recommendation percentage, review count, follower count and talking-about count. Reviews are collected newest-first, deduplicated by review ID, and can be filtered by date, keyword, or recommendation status.

    What this actor does

    • Two input styles: full Facebook page or /reviews URLs, and numeric Page IDs or page usernames
    • Deep review history: returns up to 2,000 reviews per run; Facebook serves roughly 2–3 reviews per request, so depth comes from pagination rather than a login session
    • Rich review fields: recommendation status, full text, author name/profile/photo, reaction counts and breakdowns, recommendation tags, share and comment counts, top comments, and business owner replies
    • Page-summary row: one recordType: page record per page with recommend %, total review count, followers, and talking-about count
    • Filters and monitor mode: date range, keyword, Recommended / Not Recommended, and an incremental mode that returns only reviews newer than the saved state
    • Empty fields are omitted: missing values are left out instead of being returned as null

    Use cases

    • Reputation monitoring — track new Recommended / Not Recommended reviews and owner replies for a brand or franchise location
    • Competitor analysis — compare recommendation percentages, review volume, and recurring complaint keywords across competing businesses
    • Local business research — pull reviews for restaurants, hotels, or service providers before choosing where to eat, stay, or book
    • Customer feedback analysis — export review text and recommendation tags for sentiment or NLP pipelines
    • Franchise tracking — scrape many location-specific Page IDs in one run and compare performance
    • Market research — measure follower and talking-about counts alongside review trends

    Questions

    Does this require a Facebook account or cookies?

    No. The actor reads publicly visible reviews from public business pages without logging in. Cookies are optional. They do not increase review depth: Facebook serves the same 2–3 reviews per request either way.

    How many reviews can I get?

    Up to 2,000 per run. Facebook returns about 2–3 reviews per request even when asked for more, so 100 reviews typically needs around 35–40 requests. Earlier versions of this actor described a 10–15-review limit; that was a browser-UI ceiling, not a server-side cap, and no longer applies to this collection path.

    Why is there no star rating?

    Facebook business pages use binary Recommended / Not Recommended, so there is no per-review star rating. isRecommended tells you which one the reviewer chose.

    Does recommendPercent match the reviews I received?

    No. It is Facebook's own page-level figure and is not recalculated from the returned sample, which may be a small slice of the page's full review history.

    Can I get the business's replies?

    Yes. Visible comments appear in topComments, and ownerReplies contains only the comments written by the page itself. Both are omitted when includeReplies is off, while commentCount remains.

    Can I get review photos, a language filter, or a rating distribution?

    Not from this surface today. Review photos are effectively absent on current Facebook review pages, review text has no language metadata, and no rating distribution is exposed — only the recommendation percentage and total review count. The actor does not fabricate those fields.

    Do I need to configure a proxy?

    No. The actor works without a proxy and selects a working connection automatically. The proxyConfiguration field is only for users who need a specific setup.

    How does monitor mode know what is new?

    It stores the review IDs it has seen in a named key-value store that persists across runs, one key per page. Scheduled runs with onlyNew return only reviews that were not in that saved set. Use stateKey if you want separate monitor streams for the same page.

    What happens for a dead or private page?

    The actor validates the page before collecting and writes a single recordType: "error" row. It does not guess a page URL from a business name, and it does not retry a dead page repeatedly.

    Limits and notes

    Error rows

    Unavailable pages produce a row with recordType: "error", an errorType, a readable error, the page identity when known, and scrapedAt. Error types include INVALID_INPUT, PAGE_UNAVAILABLE, PAGE_NOT_FOUND, BLOCKED, DOC_ID_UNAVAILABLE, REQUEST_FAILED, NO_REVIEWS, TIME_BUDGET_EXCEEDED, and SCRAPE_ERROR.

    Limitations

    • 2,000-review cap per run — a deliberate ceiling that keeps one run bounded
    • Public business pages only — private pages, personal profiles, groups, and Marketplace listings are not supported
    • No rating distribution or language filter — Facebook does not expose either on the reviews surface
    • Review photos are rare — the field is kept for compatibility but is usually absent
    • Reviewer identity is not always stable — authorIdType reports whether the author ID is a stable numeric ID or a rotating pfbid token
    • Facebook can change its internal review operation — the actor detects a rotated operation identifier and refreshes it, but a major upstream change can still require an actor update
