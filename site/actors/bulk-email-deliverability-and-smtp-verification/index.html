    Bulk Email Deliverability & SMTP Verification is an Apify Actor published by Nimbryxo Studio. It accepts 14 input fields, none of them required at the top level. Each result can carry up to 25 declared fields, including email, verdict, confidence, riskLevel, recommendedAction and mxProvider. It costs $0.99 per 1,000 results on Apify's Free plan and $0.49 on the Business plan.

    What it does

    The full README, with every mode, example and answer the publisher documents, is on the Apify Store page. Its sections: “What it checks”, “Output per email”, “Input”, “How to read the verdict”, “SMTP is best-effort, by design” and “Domain health coverage”.

    What you get

    The Actor saves one record per result to an Apify dataset. Its build declares 25 fields in 2 dataset views, and the README documents 3 more. Fields without a value can be left out of a record.

    Run it

    Set APIFY_TOKEN to your Apify API token, then run the Actor with the input below (clean a pasted list). Each run is billed to your Apify account. The export tutorial turns the results into a CSV file or an Excel workbook.

    Keep the first run small: maxEmailsPerDomain (default 100, maximum 10000) caps how many results a run collects, and so what it costs.

    What it costs

    Bulk Email Deliverability & SMTP Verification uses pay-per-event pricing: a fee for each result saved to the dataset, plus a start fee per run. Paid Apify plans pay less per result. The start fee is charged once per GB of run memory (at least once); the default run uses 4 GB, so a run starts with 4 start events, as the run totals include. You also pay Apify platform usage (compute and proxy) for the run, which these totals do not include.

    Input reference

    All 14 fields of the published input schema, in the publisher's order. No field is required at the top level, but the README can describe conditions. Download the input schema as JSON.

    Input fields in the published schema
    FieldTypeDescription
    emailsEmail AddressesarrayOne email address per item. You can paste a list here or use the text box below; if both are filled, the actor verifies both. Duplicates are removed case-insensitively.Example ["test@gmail.com"]
    emailsTextEmail Addresses (text)stringPaste a list separated by new lines, commas, semicolons or spaces. Useful for CSV exports and email lists.
    datasetIdRead emails from an existing datasetstringOptional Apify dataset ID. The actor reads one email per item from datasetEmailField, verifies those addresses, and can carry the original columns into each record.
    datasetEmailFieldDataset email fieldstringColumn name that holds the email address when datasetId is set.Default "email"
    includeSourceFieldsCarry source dataset columnsbooleanWhen reading from a dataset, include the original row in sourceData so you can join the verification result back to your CRM export.Default false
    verificationDepthVerification DepthstringBasic checks syntax, MX records and the A/AAAA fallback. Standard adds disposable, role-based, free-provider and domain-health checks. Deep adds a best-effort SMTP mailbox probe and catch-all detection.Default "standard"; Example "basic"; Allowed basic, standard, deep
    concurrencyConcurrencyintegerHow many addresses are checked in parallel. Higher is faster, but mail servers may rate-limit SMTP probes.Default 10; Allowed 1 to 50
    maxEmailsMaximum EmailsintegerUpper bound on unique addresses to verify in one run. Anything beyond this is skipped and reported in the run summary.Default 10000; Allowed 1 to 100000
    maxEmailsPerDomainMaximum Emails per DomainintegerCap on addresses verified for the same domain. Extra addresses get an 'unknown' record explaining the cap instead of hammering one mail server.Default 100; Allowed 1 to 10000
    smtpTimeoutSMTP Timeout (seconds)numberConnect and response timeout for each SMTP probe. Use a lower value for fast scans and a higher value for slow mail servers.Default 10; Allowed 1 to 60
    maxRetriesMax RetriesintegerExtra attempts for temporary DNS, connection and SMTP 4xx failures, using exponential backoff.Default 2; Allowed 0 to 5
    checkSmtpCheck SMTP MailboxbooleanRun the best-effort SMTP mailbox probe even at basic or standard depth. Deep depth already includes it.Default false
    checkCatchAllDetect Catch-all DomainsbooleanProbe a random address to detect catch-all domains. Implies SMTP probing. Deep depth already includes it.Default false
    includeDomainHealthInclude Domain HealthbooleanAdd SPF, DMARC policy and common DKIM selector findings for each domain at standard or deep depth.Default true
