    GitHub Repository Metadata & README Extractor is an Apify Actor published by Nimbryxo Studio. It accepts 9 input fields, none of them required at the top level. Each result can carry up to 14 declared fields, including fullName, htmlUrl, description, primaryLanguage, stars and forks. It costs $0.99 per 1,000 results on Apify's Free plan and $0.49 on the Business plan.

    What it does

    Pull structured metadata for any public GitHub repository — stars, forks, topics, license, language breakdown, and the README text — either from a GitHub search query or a list of repository URLs you already have. Supplying a personal access token is optional and only raises how many repositories you can pull per run.

    What this actor does

    • Search mode — run any GitHub search query (stars:>10000 language:python, topic:llm, user:apify) and get up to 1000 matching repositories, each fully enriched
    • Direct mode — supply a list of github.com/owner/repo URLs and fetch them directly
    • README text — fetched and decoded inline, truncated at 500 KB for very large files
    • Topics and language breakdown — the repository's topic tags and a byte count per programming language, each toggleable
    • Fields a repository doesn't have (e.g. homepage, license) are omitted from its record rather than returned empty

    Use cases

    • Ecosystem mapping — enumerate every repository tagged topic:llm or topic:web3 to build a competitive map
    • Dependency due diligence — gather license, archived status, and push cadence for a list of libraries you depend on
    • Leaderboards and dashboards — rank a set of repositories by stars, forks, or recent activity
    • Market research — compare language mix and topic distribution across a population of related projects
    • Downstream analysis pipelines — seed a static-analysis or ML pipeline with enriched repo metadata and README text

    • license — spdxId, name, url

    • isFork, isArchived, isDisabled, isTemplate — status flags
    • defaultBranch
    • readme — decoded README text, truncated at 500 KB, when includeReadme is enabled
    • languages — byte count per language, when includeLanguages is enabled
    • scrapedAt — ISO timestamp of the scrape

    When a specific repository can't be fetched, the actor emits an error record instead with type: "github_repo_intelligence_error", a reason code (rate_limit, not_found, invalid_url, search_failed, no_results, fetch_failed), a message, the repoIdentifier that failed, and scrapedAt — so one bad URL doesn't stop the rest of the run.

    Questions

    Do I need a GitHub token?

    Not for small runs — a handful of repositories works without one. For larger runs, supply a personal access token to raise your hourly request budget significantly; create a classic token with the public_repo scope at github.com/settings/tokens.

    Why would I turn off includeReadme, includeTopics, or includeLanguages?

    Each one adds an extra fetch per repository; disabling what you don't need lets a single run cover far more repositories within the same request budget.

    Do I need a proxy?

    No — GitHub's API access isn't IP-rate-limited in a way that requires one.

    Can I scrape private repositories?

    Yes, as long as the githubToken you supply has access to them — a classic token with repo scope covers all private repositories your account can read.

    Why are some fields missing from my output?

    Only fields with real data are included — a repository without a homepage simply has no homepage key, rather than a null.

    How large can a README get?

    READMEs are truncated at 500 KB of decoded text with a ...[truncated] marker, which covers the vast majority of real-world READMEs in full.

    Can search return more than 1000 results?

    No — that's GitHub's own hard cap on search results. For a larger universe, split the query into ranges (e.g. stars:1000..5000, then stars:500..999) and run once per range.

    What happens if one repository fails?

    The actor emits an error record for that repository and continues with the rest of the batch, so one deleted or private URL doesn't stop the run.

    Is this affiliated with GitHub?

    No — this is an independent actor built on GitHub's public REST API; it is not operated by GitHub.
