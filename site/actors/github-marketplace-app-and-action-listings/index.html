    GitHub Marketplace App & Action Listings by Category is an Apify Actor published by Nimbryxo Studio. It accepts 12 input fields, and mode is required. Each result can carry up to 9 declared fields, including name, listingType, slug, installedCount, stars and planType. It costs $0.99 per 1,000 results on Apify's Free plan and $0.49 on the Business plan.

    What it does

    Collect structured data on GitHub Marketplace apps, integrations and GitHub Actions without a GitHub account, OAuth token or API key. Search by keyword, browse any of the 34 marketplace categories, or look up exact listings by slug or URL.

    What this actor does

    • Search apps and integrations by keyword across the whole marketplace
    • Search GitHub Actions as a separate listing type
    • Search both at once and get the two types interleaved by marketplace rank
    • Browse a category — 34 real marketplace categories, for apps or Actions
    • Look up exact listings by slug, marketplace path or full URL; app and Action forms are detected automatically
    • Filter by pricing — free trial (server-side), has a free plan, has a paid plan
    • Filter by verified creator — only listings from GitHub-verified publishers
    • Filter by publisher login, minimum installs or minimum Action stars
    • Sort by best match, popularity/installs or recently added
    • Paginate to the marketplace's own limits — 20 listings per page, up to your maxItems

    Every record is built from the marketplace's own embedded JSON, not from marketing HTML, so pricing plans, install counts, publisher details, permissions and Action repository stats are exact values rather than guesses.

    Use cases

    • DevOps tooling research — compare CI/CD, deployment and monitoring integrations before adding one to a pipeline
    • Vendor and market mapping — catalog every listing in a category, with install counts and pricing tiers
    • Pricing benchmarking — collect monthly/yearly and per-seat prices, free plans and trial lengths in one dataset
    • Action due diligence — compare Action stars, latest releases, contributors and open issue counts
    • Publisher tracking — filter a search or category down to specific GitHub accounts
    • Link collection — resolve a list of slugs or URLs into canonical marketplace records

    • pricing[] — plan name, description, monthly/yearly price in cents, formatted price, per-unit flag, unit name, free-trial flag, paid flag, bullets and plan ID
    • installedCount (apps), stars (Actions)
    • verifiedPublisher, publisherName, publisherLogin, publisherUrl, publisherAvatarUrl, publisherType
    • brandColor, documentationUrl, privacyPolicyUrl, tosUrl, statusUrl, supportUrl, supportEmail, pricingUrl
    • recordType (always githubMarketplaceListing), scrapedAt (ISO-8601 UTC)

    App-specific fields:

    • businessId, euTrader, traderAddress, publisher2faRequired, transparencyDisclosure
    • thirdPartyServices (GitHub's own declaration; it can literally be None when the publisher declares no third-party services), verifiedDomain, verifiedProfileDomains, supportedLanguages
    • permissions[] — scope, permission level and the granted values
    • repositoryUrl, repositoryVisibility, listableType, isCopilotApp

    Action-specific fields:

    • usesRef — the owner/repo@ prefix used in workflow files

    • latestRelease and releases[] — tag name, release name and pre-release flag

    Empty fields are omitted rather than returned as null or a blank value.

    Questions

    Do I need a GitHub account, token or proxy?

    No. The actor reads public GitHub Marketplace pages with no authentication, cookies or proxy configuration.

    Why are install counts exact for apps but Actions use stars?

    GitHub Marketplace publishes an installation count on app listings. Action listings publish the source repository's star count instead; the actor returns whichever metric the listing actually has.

    How does pricing filtering work?

    free_trials uses GitHub's own free-trial filter. free and paid are checked against each listing's published plans after the detail page is read, so they are exact rather than text guesses. A listing with both a free plan and a paid plan counts as having both; planType reports paid as the primary type while hasFreePlan stays true. Actions are not sold through Marketplace billing plans, so the free, paid and free_trials filters return apps only; use minStars to filter Actions.

    Why can a narrow filter take longer?

    minInstalls, minStars, owners and the free/paid checks are applied after each listing's detail page is read, because GitHub does not expose them as server-side filters. The actor stops after a bounded number of consecutive pages with no match rather than scanning the entire catalogue.

    Why is there no rating field?

    GitHub Marketplace does not publish star ratings or review scores for listings. The actor does not invent one.

    Why are screenshots missing?

    GitHub serves listing screenshots from signed URLs that expire after five minutes. Shipping them would produce broken links; the listing url opens the gallery instead.

    How many listings can I get?

    Apps: all 1,408 currently listed. Actions: GitHub caps a single query at 500 result pages (10,000 listings); use a narrower keyword or category to reach different slices. maxItems is capped at 1,000 per run.

    Does it cover AI model listings?

    No. GitHub Marketplace also lists AI models, but they use a different schema (no slug, model registry fields). This actor focuses on apps, integrations and Actions.

    Does it monitor changes between runs?

    No. It is a stateless collector; save each dataset and compare snapshots on your side.

    Is this affiliated with GitHub?

    No. It is an independent actor that reads GitHub Marketplace's public pages.

    Limits and notes

    Limitations

    • No ratings or reviews (GitHub Marketplace has none).
    • Screenshot URLs are signed and expire; they are not emitted.
    • One Action query reaches at most 500 pages / 10,000 listings (GitHub's cap). Split by category, keyword or sort order for wider coverage.
    • Support email, repository URL and some legal fields are published only for a subset of apps; they are omitted when absent.
    • Action README content is not emitted; the listing url links to it.
    • The actor does not install apps or Actions and does not access private repositories.
